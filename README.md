# Live Korean Captions

영어 화자 한 명의 목소리를 듣고 한국어 자막을 표시하는 독립 Mac 앱입니다.

[GitHub 저장소](https://github.com/SeoJHeasdw/live-ko-catption)

`live-ko-caption`은 상위 `javis` 폴더의 에셋·음악·TTS 엔진과 설정, 의존성, 실행 과정을 공유하지 않습니다. 서버나 API 키 없이 Apple의 기기 내 음성 인식과 번역을 사용합니다.

## 사용하기

1. `dist/Live Korean Captions.app`을 엽니다.
2. 처음에는 **언어 모델 준비**를 누릅니다. 영어 음성 인식과 영어·한국어 번역 모델을 받는 동안 인터넷이 필요합니다. 시스템에서 다운로드 허용을 요청하면 승인합니다.
3. 핀마이크 수신기를 Mac에 연결하고 입력 장치를 선택합니다. 목록에 없으면 새로고침을 누릅니다.
4. **자막 시작**을 누릅니다. 처음에는 macOS의 마이크 접근 허용이 필요합니다.
5. 영어 화자가 말하면 원문과 한국어 자막이 표시됩니다. **잠시 멈추기**는 현재 대화를 유지합니다.
6. **원문·자막 저장**으로 텍스트 파일을 저장할 수 있습니다. 자동 저장이나 원본 음성 녹음은 하지 않습니다.

모델 준비 후 음성 인식과 번역은 Mac 안에서 처리합니다. 앱은 번역용 외부 서비스에 연결하지 않습니다. 실제 오프라인 동작은 언어 모델 준비 후 네트워크를 끄고 확인해야 합니다.

## 자막 동작

- 아직 확정되지 않은 자막은 연한 회색으로 표시하고, 발화 중에 수정합니다.
- 음성 인식 결과가 확정되고 그 문장의 정확한 버전이 번역됐을 때 진한 색으로 바뀝니다.
- 이전 번역이 늦게 도착해도 최신 문장을 덮어쓸 수 없습니다.
- 번역은 한 번에 하나씩 진행합니다. 새 확정 원문은 오래 걸리는 초안·문맥 보정을 취소하고 먼저 처리합니다. 같은 원문이 그대로 확정되면 진행 중인 번역을 재사용합니다. 초안은 최신 버전만 유지해 약 0.55초 간격으로 갱신합니다. 이는 갱신 간격이며 전체 자막 지연을 보장하는 수치가 아닙니다.
- **최근 구절을 문맥으로 함께 번역**을 켜면 이미 번역된 최근 2~4개 구절을 다시 번역합니다. 한 묶음은 12초·영문 500자 이내이며, 긴 무음이나 일시정지를 넘어 연결하지 않습니다. 확인 중에는 회색으로 돌아가고 번역이 완료되면 하나의 문맥 묶음으로 표시합니다. 원래 음성 인식 구절과 시간은 유지하고, 이전 묶음은 반복 수정하지 않습니다.
- 문맥 보정에는 로컬 `highFidelity` 전략을 요청합니다. [Apple의 전략 설명](https://developer.apple.com/documentation/translation/translationsession/strategy/highfidelity)에 따르면 Apple Intelligence를 사용할 수 없으면 기존 번역 모델로 돌아갈 수 있으며, 이 Mac의 비교에서는 두 전략의 결과가 같았습니다. 자연스러운 의역이나 의미 정확성을 보장하지 않습니다.
- 번역 오류가 난 자막은 확정된 것처럼 표시하지 않습니다. 원문과 오류 표시를 유지하며 다시 번역할 수 있습니다.
- 화면 위쪽의 자막만 보기와 전체 화면 버튼으로 발표용 화면을 사용할 수 있습니다.
- 자막을 직접 스크롤하면 자동 따라가기를 멈춥니다. 위쪽 버튼으로 다시 켤 수 있습니다.

## 요구 사항과 빌드

- Apple Silicon Mac
- macOS 26.4 이상
- 빌드할 때 Swift 6 이상과 Command Line Tools 또는 Xcode
- 패키지 의존성 없음

```sh
./scripts/build-app.sh
open "dist/Live Korean Captions.app"
```

빌드 스크립트는 독립 `.app` 번들을 만들고 로컬 실행용 임시 서명을 합니다. App Store 배포나 Developer ID 서명은 포함하지 않습니다. 현재 Command Line Tools 환경에서는 SwiftPM의 native 빌드 방식을 사용합니다.

## 검증

### 0.2.2 연속 사용 안정화

1분 이상 사용 후 응답이 없던 앱을 종료하기 전에 조사했습니다. 화면 배치·자동 스크롤 계산이 반복되며 메모리가 커지는 상태를 확인해, 자막 표시를 고정된 영역의 네이티브 텍스트 화면으로 바꿨습니다. 최근 **100개 표시 구절**만 그리며, 전체 원문·번역은 모델과 **원문·자막 저장**에 보존합니다. 문맥 묶음은 중간에서 잘리지 않습니다. 과거 전체를 화면에서 탐색하는 기능은 아직 없습니다.

원문 수정은 최신 상태로 합쳐 최대 초당 10회 갱신합니다. 마이크 레벨 변화가 창 전체를 다시 배치하지 않도록 분리했고, 알림을 닫은 뒤에도 실패한 번역을 다시 시도할 수 있습니다. 작은 마이크 입력은 변환 큐에서 약 100ms로 묶어 분석 큐의 여유를 늘렸습니다. 입력 콜백에서 인식·번역을 실행하지 않으며, 정지 때 마지막 짧은 입력도 배출합니다.

실제 로컬 엔진의 **30분 입력 + 30초 재시작**, 별도 창의 **30분 합성 표시**, 최종 앱의 **내장 마이크 20분 40초 + 재시작**을 통과했습니다. 엔진 검사는 확정 원문 451개 보존, 입력 누락·번역 실패·종료 후 네이티브 응답 대기 0개를 확인했습니다. [원자료와 조건](docs/qa/continuous-stability.txt)에 초기 종료 실패, 수정, 검사별 범위와 한계를 함께 남겼습니다. 실제 화자·핀마이크의 30분 사용이나 의미 정확성을 대신하지 않습니다.

```sh
./scripts/check-continuous-pipeline.sh
./scripts/check-ui-soak.sh
```

각 명령은 기본 30분 동안 실행됩니다. 첫 명령은 설치된 음성·번역 엔진을 사용해 합성 영어를 반복 입력한 뒤 정지·재시작합니다. 두 번째 명령은 별도 시험 앱에서 실제 창을 갱신하며 영어 표시·글씨 크기·창 크기도 변경합니다. 시험 앱은 합성 검사임을 표시하고 실제 번역 성능 수치를 표시하지 않습니다. 현재 실행 중인 사용자 앱과 대화는 시험 앱이 바꾸지 않습니다.

### 0.2.1 실제 마이크 시작·재시작 수정

0.2.0의 첫 실제 실행에서 선택한 내장 마이크가 AVAudioEngine의 시스템 기본 Bluetooth 입력으로 바뀌고, 오디오 버퍼가 도착하지 않아 3초 뒤 정지하는 결함을 확인했습니다. 0.2.1은 출력 장치와 독립적인 입력 전용 AudioUnit에 선택한 마이크를 고정하고, 실제 장치 ID와 네이티브 음성 형식을 확인합니다.

첫 입력과 입력 연결 복구 대기는 **20초**입니다. 말하지 않는 무음 버퍼도 정상 입력으로 처리하므로 조용히 기다린다고 정지하지 않습니다. 입력 오류로 중단되면 늦은 작업을 차단하고 시작 버튼을 즉시 복구합니다. 정상적인 ‘잠시 멈추기’는 마지막 문장을 정리합니다.

수정본의 실제 내장 마이크로 두 번의 시작·정지를 합쳐 3분 이상 확인했습니다. 선택한 입력은 네이티브 48kHz로 유지됐고, 두 번 모두 20초 넘게 듣는 상태를 유지했으며 입력 누락 0개와 정지 후 시작 버튼 활성화를 확인했습니다. [실제 마이크 검증 기록](docs/qa/2026-09-30-microphone-recovery.json)은 입력 연결·대기·재시작 검증이며 영어 인식·번역 정확성 측정은 아닙니다.

### 2026-09-30 적대적 리뷰와 개선

실 사용 판정은 **일상 영어를 따라가는 보조 자막으로 제한적으로 활용 가능, 자연스러운 통역의 대체는 아직 부족**입니다. 진한 글씨는 현재 확정 원문의 정확한 버전이 번역됐다는 뜻이며, 번역의 의미가 검증됐다는 뜻은 아닙니다.

리뷰에서 스테레오 수신기의 오른쪽 음성이 모노 변환에서 사라지는 문제, 정지 시 마지막 입력 누락, 입력 대기 누적, 시작 취소 후 늦은 작업의 재실행, 번역·정리 작업의 무기한 대기를 보완했습니다. 입력 장치가 사라지거나 음성 형식이 바뀌면 누락 가능성을 알리고 정지합니다. 변환 대기는 입력 0.5초 이내, 분석 스트림은 8개 버퍼로 제한하고 누락 횟수를 기록합니다.

번역 응답은 6초, 문맥 보정은 4초, 정지 정리는 전체 8초까지 기다립니다. 문맥 보정 실패 시 기존 번역을 유지합니다. 번역 대기가 계속 늘면 입력을 멈추고 미완료 원문을 보존해 재시도할 수 있게 합니다. 이 수치는 성능 보장이나 목표 지연이 아닌 오류 회복의 상한입니다.

실제 로컬 번역 20개 입력을 두 전략으로 비교했습니다. 이어지는 `not only … but also`를 함께 번역하면 앞부분의 부정 해석이 수정됐습니다. 반면 `duck`의 동작·동물 구별, 실제 케이크와 관용구 구별, 전문 용어, 고유명사, `below`의 수치 경계, 원문에 없는 오후 시간 추가는 실패했습니다. [판정과 실패 사례](docs/qa/translation-quality-review.txt), [실제 번역 결과](docs/qa/2026-09-30-translation-quality.json)를 확인할 수 있습니다.

[전체 리뷰와 실 사용 판정](docs/qa/adversarial-review.txt)은 수정한 결함, 검사 범위와 남은 한계를 정리합니다. 실제 앱 스케줄러에 로컬 인식·번역을 연결한 [15.627초 합성 영어 검사](docs/qa/2026-09-30-realtime-pipeline.json)에서는 확정 원문 6개 보존, 진한→회색 문맥 확인 전환 4회, 입력 누락 0개를 확인했습니다. 해당 음성 구간 끝부터 최신 번역이 화면 모델에 반영되기까지 18개 관찰의 중앙값은 0.597초, 최대는 1.140초였습니다. 준비된 모델·단일 합성 파일의 결과이며 마이크 하드웨어·화면 그리기 시간과 실제 사람·장시간 사용을 포함하지 않습니다.

상태·스케줄러·실제 앱 모델의 동작을 마이크 없이 재현하려면:

```sh
swift run --build-system native CaptionCoreChecks
swift run --build-system native TranslationSchedulingChecks
./scripts/check-lifecycle.sh
./scripts/check-app-model.sh
./scripts/check-audio-callbacks.sh
./scripts/check-translation-leases.sh
swift run --build-system native LocalPipelineCheck --translation-quality --compare-strategies
./scripts/check-realtime-pipeline.sh /absolute/path/to/english-audio.aiff --output /tmp/caption-report.json
```

앱 모델 검사는 번역기를 주입해 오래 걸리는 작업, 회색→확정·문맥 보정, 취소·우선순위·재시도·미완료 원문 보존을 재현합니다. 짧은 합성 영어의 로컬 파일 검사에서도 최종 음성 인식 구절 6개를 모두 보존했습니다. 이 짧은 검사들은 실제 핀마이크, 사람의 발음·소음, 20~30분 연속 사용, 네트워크를 끈 실행을 대신하지 않습니다. 별도의 장시간 검사 범위는 0.2.2 항목을 따릅니다.

### 0.1.1 마이크 충돌 수정

0.1.0에는 실제 마이크의 첫 입력에서 앱이 종료되는 결함이 있었습니다. MainActor 안에서 만든 AVFoundation 콜백이 음성 처리 큐에서 호출되면서 Swift의 실행 영역 검사를 위반했습니다. 파일 인식 검증만으로는 이 결함을 발견할 수 없었습니다.

0.1.1은 콜백을 화면 실행 영역과 분리하고, 불필요한 마이크 재설정을 피합니다. 초기 I/O 설정으로 엔진이 멈추더라도 음성 형식이 같으면 최대 두 차례 자동으로 다시 연결합니다. 연속 음성 분석은 별도 작업에서 수행하며, 입력 종료 후 분석·자막 결과를 정리합니다. 시작 중의 입력 오류도 무시하지 않습니다. 일시정지 후 자막 시간은 이전 녹음의 무음 구간을 포함해 이어집니다.

콜백과 실제 로컬 스트리밍 분석을 확인하려면:

```sh
./scripts/check-audio-callbacks.sh
./scripts/check-audio-callbacks.sh /absolute/path/to/english-audio.aiff
```

첫 명령은 마이크를 열지 않고 음성 큐의 실행 영역, 두 PCM 형식의 변환, 설정 변경 알림 전달을 확인합니다. 두 번째 명령은 테스트 파일을 100ms 단위로 보내 실제 음성 인식·자막 구간 유지·입력 종료·한국어 번역을 확인합니다. 준비된 언어 모델이 필요합니다. 이 테스트는 마이크 하드웨어 지연을 측정하지 않습니다.

수정 중 MacBook Pro 내장 마이크로 두 번의 실행을 합쳐 약 4분 동안 입력·정지를 확인했고, 테스트 영어를 마이크로 받아 한국어 자막을 표시했습니다. 추가로 발견한 시작 대기 처리까지 바꾼 최종본은 스트리밍 파일 검증을 통과했습니다. 최종본의 내장 마이크 반복 검증은 Mac 잠금 해제 후 진행해야 합니다.

```sh
swift run --build-system native CaptionCoreChecks
```

검증 프로그램은 뒤늦은 번역, 확정 시점, 수정된 음성 구간, 중복 번역, 미확정 기록 내보내기를 확인합니다. XCTest나 Swift Testing 설치 없이 실행할 수 있습니다.

언어 모델 준비 후 실제 영어 음성 파일로 두 로컬 엔진의 연결을 확인할 수 있습니다. 이 검증은 마이크를 열거나 모델을 다운로드하지 않습니다.

```sh
swift run --build-system native LocalPipelineCheck /absolute/path/to/english-audio.aiff
```

2026-09-30, 이 Mac에서 5.38초의 테스트용 영어 음성 파일을 점검했습니다. 음성 인식은 약 0.30초, 텍스트 번역은 약 0.90초였고, 21개의 중간 인식 결과가 반환됐습니다. “The meeting starts at three thirty. We cannot approve this plan yet.”는 “회의는 3시 30분에 시작합니다. 아직 이 계획을 승인할 수 없습니다.”로 번역됐습니다. 이는 음성 파일을 빠르게 처리한 단일 점검 결과이며 실시간 마이크 지연을 측정한 값이 아닙니다.

화면만 확인하려면:

```sh
open "dist/Live Korean Captions.app" --args --preview
```

미리보기의 문장은 예시 데이터이며 실제 음성 인식·번역 결과나 성능 측정값이 아닙니다.

실제 지연과 번역 품질은 다음 순서로 확인합니다.

1. 언어 모델을 준비하고 핀마이크로 자막을 시작합니다.
2. 짧은 영어 문장, 문장 중간의 정정, 숫자·고유명사, 길게 이어지는 설명을 말합니다.
3. 회색 문장이 동적으로 수정되는지, 진한 자막이 최근 문맥 확인 동안 다시 회색으로 바뀌어 수정되는지, 오래된 묶음은 유지되는지 확인합니다.
4. 일시정지·재시작, 마이크 분리, 기록 저장을 확인합니다.
5. 인터넷을 끈 상태에서 다시 시작합니다.
6. 20~30분 대화 중 번역 대기가 누적되는지 확인합니다.

하단의 **자막 도착**은 음성 구간의 끝부터 현재 구절의 한국어 번역 반영까지의 추정 시간이고, **인식 지연**은 인식 결과 도착까지의 추정 시간이며, **최근 번역**은 마지막 텍스트 번역 호출 시간입니다. 마이크 하드웨어 지연은 포함하지 않으며 개별 호출 시간만 전체 자막 지연으로 해석하면 안 됩니다. 첫 번째 시험 목표는 짧은 구절 이후 읽을 만한 자막이 1~3초 안에 나오는 것이지만 실제 측정으로 확인해야 합니다.
