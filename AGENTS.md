# Project instructions

- The user prefers feature-based commits and separate pushes for each feature. Keep each commit buildable and push each completed feature separately unless the user requests a different workflow. The configured remote is the user-provided `https://github.com/SeoJHeasdw/live-ko-catption`.

- This is an independent, native macOS app for one speaker at a time with a manually selected English→Korean or Korean→English direction. The direction is chosen before a conversation and can be switched manually inside it; it is never inferred from speech, and each caption keeps the direction it was made in. Keep it isolated from the sibling asset, music, and TTS engines. Do not import their configuration, dependencies, model servers, or launch scripts.
- Preserve fully local inference after initial language/model downloads. The optional Hy-MT2-1.8B Q6_K model refines final sources only; Apple remains the fast caption path. Keep model weights out of Git and verify the pinned size/digest before loading. Do not add cloud services. System-audio capture was requested on 2026-10-01: it is a user-selected input through a private Core Audio process tap, never the default, never written to disk, and it uses the same bounded pump path as a microphone.
- Keep audio callbacks small. Recognition and translation must not run on the audio callback. Bound audio queues and report dropped input honestly.
- Construct AVFoundation's foreign-thread callbacks in a nonisolated factory. Do not create an `AVAudioNodeTapBlock` inside a MainActor method: Swift 6 can infer MainActor isolation and trap at the first real microphone buffer. Use `AudioPump.makeTapBlock()`, `AudioPump.makeSilenceTimer()` and `AudioCallbackBridge`, and run `./scripts/check-audio-callbacks.sh` and `./scripts/check-system-audio.sh` after audio changes.
- Provisional captions remain gray and editable in either direction. A caption becomes final only when its ASR source is final and the exact current source revision has been translated. Optional refinement keeps the fast baseline visible, runs one request at a time on its own lane, and must never delay the fast translation of a following draft or final source; an older waiting sentence keeps its baseline when the lane falls behind. Reject stale translation results. Never rewrite recognized or translated text with built-in word substitutions; the only corrections are the spellings the user listed in their own glossary file, applied when that personal dictionary is selected. That file stays on the user's Mac and customer-specific terms never go into this repository.
- Keep finalized text stable. Do not translate the complete session history for every partial update. Coalesce partial work and prioritize final results.
- Build with `./scripts/build-app.sh`. Run `swift run --build-system native CaptionCoreChecks` when modifying caption state or translation scheduling.
- UI preview data must be clearly labeled and must not contain invented performance measurements. Build success and state checks do not prove live microphone accuracy or latency.
- Before adding SDK APIs, check their actual minimum OS version; the current SDK is newer than the supported macOS 26.4 deployment target.
