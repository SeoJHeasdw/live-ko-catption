2026-09-30 · 0.2.2 연속 사용 안정화

현재 판정: 신고된 화면 응답 없음과 번역 취소 후 미종료 요청을 수정했다.
수정본의 실제 로컬 엔진 30분 입력·종료·재시작, 별도 창의 30분 표시 검사,
최종 앱의 내장 마이크 20분 40초 입력·재시작 검사를 통과했다.

사용자가 남겨둔 응답 없는 앱의 진단

0.2.1 프로세스를 종료하기 전에 실행 중인 스택과 메모리 상태를 수집했다.
메인 스레드 표본 3,571개 중 대부분이 SwiftUI/AttributeGraph의 화면 배치와
RootGeometry 계산에 머물렀다. 당시 physical footprint는 3.2GB였으며 이후에도
늘었다. 이는 프로세스가 종료된 충돌보다 화면 실행 영역이 바빠 응답하지 못하는
상태였다. 표본만으로 Apple 프레임워크 내부의 원인을 완전히 단정할 수는 없지만,
반복 갱신되는 전체 자막 목록과 자동 스크롤·높이 계산의 결합을 제거할 근거가 됐다.

수정

- 자막은 고정된 화면 영역의 네이티브 NSTextView/NSScrollView로 표시한다.
  실시간 표시를 최근 100구절로 제한하고, 전체 원문·번역·수정 상태는 모델과
  저장 기록에 보존한다. 문맥 묶음이 표시 경계에서 잘리지 않도록 한다.
- 새 원문을 모두 그리는 대신 가장 최근 상태로 합치고, 변경된 뒤쪽만 갱신한다.
  화면 갱신은 최대 초당 10회, 자동 따라가기는 최대 초당 5회다. 마지막 갱신도
  화면에 도착하도록 별도 후속 갱신을 둔다.
- 마이크 레벨의 잦은 변화가 전체 창과 자막 배치를 다시 계산하지 않도록 화면
  관찰 범위를 나눴다. 조작 패널의 높이가 창 높이에 다시 영향을 주는 구조를 없앴다.
- 사용자가 스크롤하면 따라가기를 멈춘다. 번역 실패 알림을 닫아도 다시 번역
  버튼을 남긴다. 원문과 실패 상태도 유지한다.
- 짧은 마이크 입력을 변환 큐에서 약 100ms로 묶어 음성 분석에 전달한다. 입력
  콜백에서 인식·번역은 하지 않는다. 변환 대기 0.5초, 분석 대기 8개를 유지하고,
  48kHz/512프레임 입력에서 분석 큐의 여유를 약 85ms에서 약 0.8초로 늘렸다.
  배치 때문에 입력당 최대 약 100ms의 추가 대기가 생길 수 있다. 정지 때 짧은
  마지막 배치를 버리지 않는다. 누락은 숨기지 않는다.
- 빌드한 실행 파일은 교체 파일을 통해 원자적으로 바꾼다. 실행 중인 앱의 파일을
  직접 덮어쓰지 않는다.
- 늦은 인식 구절이 이미 합친 문맥 묶음 사이에 들어오면 해당 묶음만 해제한다.
  시간순 원문과 정확한 개별 번역으로 표시·저장하고 관계없는 문맥 묶음은 유지한다.
- 진행 중인 Apple 번역 세션을 즉시 취소하면 Swift의 응답 대기가 끝나지 않는
  사례를 실제로 재현했다. Swift 작업의 취소와 세션 정리를 나누고, 네이티브
  응답이 반환된 뒤 세션을 정리한다. 실행을 바꿔도 실제로 끝나지 않은 요청은
  계속 센다. 실시간 번역 2개·문맥 번역 2개의 상한을 두고 한도가 차면 입력을
  멈추고 원문을 보존한다. 화면상 취소를 네이티브 작업 종료로 간주하지 않는다.
  여기서 세는 것은 앱에서 반환되지 않은 SDK 호출이다. Apple의 별도 시스템
  서비스 내부 작업과 메모리 전체를 측정하거나 제한하는 수치는 아니다.

첫 30분 엔진 검사에서 발견한 종료 결함

continuous-pipeline-30m.json은 입력 1,800초를 완료했지만 전체 passed=false다.
입력 누락 0, 번역 실패 0, 확정 원문 443개 보존·정확한 원문 버전 번역을
확인했고 시작 버튼도 복구됐다. 그러나 취소된 네이티브 번역 요청 1개가 종료 후
반환되지 않아 종료 감사가 실패했다. 이 실행에서는 재시작 검사를 건너뛰었다.

별도 Apple 엔진 재현에서는 세션 취소를 요청한 24개 중 23개가 10초 후에도
반환되지 않았다. 화면·음성 인식·앱 번역 큐를 제외해도 나타났다. 반면 대표
길이의 요청을 순차적으로 Swift 작업만 취소한 검사는 24회 모두 반환됐고
매회 새 번역도 성공했다. 종료 순서를 수정한 1,620자 요청 128회 검사에서도
취소된 응답 128개가 모두 반환됐으며 매회 새 번역과 마지막 재시작도 성공했다.

Apple cancel 문서는 진행 중인 작업을 멈추려는 시도로 설명하며 반환을 보장하지
않는다: https://developer.apple.com/documentation/translation/translationsession/cancel%28%29
진행 중인 세션에 취소를 즉시 요청하는 경로를 제거하고 TranslationSessionLease로
실제 작업 생명주기를 추적한다. 수정본의 별도 30분 입력·종료·재시작 검사는 아래 결과처럼 통과했다.

검사 범위

1. 실제 로컬 엔진: 설치된 Samantha 합성 영어를 실제 시간에 맞춰 1,800초
   반복 입력한다. 실제 AudioPump → SpeechAnalyzer → 앱 번역 큐 → 설치된
   Apple 번역 세션을 사용한다. 이어서 30초 정지·재시작을 검사한다. 마이크와
   화면 그리기는 포함하지 않으며 Apple의 별도 언어 서비스 메모리도 포함하지 않는다.
2. 실제 창: 별도 앱에서 1,800초 동안 합성 상태를 실제 화면에 표시한다. 입력
   레벨은 25ms 간격, 인식 수정은 매 네 번째 입력 주기에 발생하도록 구성하며,
   실제 주기에는 처리 시간도 포함된다. 주기적인 문맥 보정·창 크기·글씨 크기·
   영어 표시 전환을 포함한다. 실제 번역 품질이나 마이크 지연을 측정하지 않는다.
3. 오디오 변환: 30분 분량의 48kHz/512프레임 입력을 빠르게 처리했다. 입력
   168,750개 → 16kHz 출력 28,800,000프레임, 누락 0개를 확인했다. 실제 실행은
   22.09초였다. 이 결과를 30분 실제 사용 검사로 세지 않는다.

실 사용의 남은 한계

실제 화자의 30분 연속 마이크 입력, 핀마이크 분리·재연결, 잠자기·깨우기,
네트워크를 끈 실행은 이번 검사와 다른 조건이다. 내장 마이크 장시간 검사는
입력 연결·대기·재시작을 확인했으며 자연 발화의 30분 품질을 입증하지 않는다.

따라가기를 끈 채 읽는 구절이 최근 100구절 안에 남아 있으면 구절 식별자와 글자
위치로 읽던 곳과 선택 영역을 유지한다. 읽던 구절 자체가 표시 범위를 벗어나면
그 구절을 화면에 계속 보존하지 않는다. 전체 기록은 저장으로 확인한다.
과거 탐색·검색·자동 저장은 아직 없다.

진한 자막은 확정된 원문과 번역 버전의 일치만 뜻한다. 의미 정확성 검증이 아니다.
용어·숫자·부정·중의어·늦은 정정의 품질 한계는 translation-quality-review.txt와
adversarial-review.txt를 따른다. 새로운 엔진·용어집은 이번 안정화 범위에 추가하지 않았다.
