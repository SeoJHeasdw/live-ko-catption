2026-09-30 · 0.3.0 (6) 간략 자막 창

현재 판정: 간략/상세 보기, 테두리 크기 조절, 공유 기록 유지와 최신 자막
표시 검사를 통과했다. 인식·번역 엔진과 오디오 콜백은 변경하지 않았다.

동작

- 실제 시작이 listening에 도달하면 반투명 검은 떠 있는 자막 창으로 전환한다.
  시작 오류는 상세 화면에 남긴다. 상세 화면을 숨겨도 준비 작업의 호스트와
  같은 CaptionModel을 유지한다. 보기 전환은 인식·번역을 다시 시작하지 않는다.
- 최근 두 표시 구절만 네이티브 TextKit 화면에 그린다. 문맥 묶음과 회색 초안
  상태를 따르며, 긴 자막은 최신 끝부분의 두 줄을 보여준다. 전체 기록은 유지한다.
- 호버 시 +/일시정지·재개/중지 컨트롤을 표시한다. 멈췄거나 오류가 있으면
  컨트롤을 남기며 오류 알림은 상세 화면으로 연결한다. 일시정지는 기존 정리
  경로를 사용하고, 중지는 기록을 지우지 않고 상세 창을 복구한다.
- 위쪽 영역은 이동, 네 테두리·모서리는 크기 조절이다. 최소 크기는 420×144이며
  창 위치·크기를 보존한다. ⌘1/⌘2는 보기 전환, ⌘.은 중지 후 상세 보기다.

검증 과정에서 고친 결함

처음 합성 검사는 빈 상세 화면에 아직 존재하지 않는 자막 문서를 요구해 실패했다.
검사를 창 준비와 첫 자막 생성으로 나눴다. 첫 간략 미리보기에서는 숨겨진 상세 창을
마지막 창 종료로 처리하므로 간략 창이 있는 동안 자동 종료하지 않게 수정했다.

문서 문자열만 확인하던 검사를 실제 마지막 글자 좌표와 네이티브 테두리 처리까지
넓히자 크기 조절 후 창이 1×1이 되는 실패가 드러났다. NSHostingView의 자동
최소 크기 계산이 패널에 지정한 최소값을 덮어썼다. SwiftUI 루트에 420×144
최소 크기를 지정하고 호스팅 크기 계산은 최소값만 사용한다. 검사는 현재 패널
최소값을 그대로 신뢰하지 않고 제품의 420×144와 독립적으로 비교한다.
두 구절 사이의 추가 문단 간격 때문에 이전 줄이 잘리던 문제도 제거했다.

15회, 간략 창 크기 변경 10회, 네이티브 테두리 입력 처리 검사 2회를 통과했다.
오른쪽·아래쪽 확대와 왼쪽·위쪽 최소 크기 제한, 반대편 테두리 고정을 확인했다.
OS에 합성 마우스 이벤트를 보내지 않고, 실제 화면 계층에서 찾은 테두리 뷰의
입력 처리 함수를 호출했다. 마지막 번역의 마지막 글자 전체가 보이는 영역에
들어왔으며, 숨긴 상세 문서·같은 모델·원문 기록·listening 상태를 유지했다.

별도 실제 앱에서 기존 내장 마이크로 시작 성공 후 자동 간략 보기 전환,
실제 마우스 모서리 크기 조절, 일시정지, + 상세 복귀, ⌘2 간략 복귀, 재개,
⌘. 중지와 준비 상태 복귀를 확인했다. 별도 예시 앱에서 상세 창 닫기 후
프로세스 종료도 확인했다. 예시 화면은 미리보기로 표시하며 성능 수치를 넣지 않는다.

./scripts/build-app.sh 통과. CaptionCoreChecks 21개와 앱 모델 검사 17개 통과.
