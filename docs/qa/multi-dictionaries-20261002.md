# 여러 용어사전 — 2026-10-02

대상은 0.5.0 (20)의 AI·IBM·금융권 복수 선택과 로컬 개인 사전 추가 기능이다. 이 자료의 자동 상태 검사와 UI 확인은 번역 의미 정확성·실제 마이크 지연을 입증하지 않는다. 실제 모델의 품질 비교는 [용어사전 번역 비교](dictionary-translation-20261002.md)에 기록한다.

## 구현과 공개 자료

- 설정 → 번역 → 용어사전 적용에서 AI·IBM·금융권을 함께 선택하고, 아무것도 선택하지 않으면 일반 번역을 사용한다. 사이드바에는 선택 요약과 설정 버튼이 표시된다.
- 공개 기본 용어 62개는 공식 자료를 확인한 AI 20개, IBM 제품명 20개, 금융권 22개다. 출처 및 보수적 적용 기준은 [AI](../research/ai-glossary-20261002.md), [IBM](../research/ibm-glossary-20261002.md), [금융권](../research/finance-glossary-20261002.md)에 있다. 내부·고객 용어와 인식 오탈자 별칭은 기본 사전에 넣지 않았다.
- 선택한 짧은 분야 설명과 실제 원문에 등장한 용어만 선택적 로컬 확정 문장 다듬기에 전달한다. 영어 복수 s/공백/하이픈, 한국어 띄어쓰기 변형은 매칭에만 쓰며 원문을 바꾸지 않는다. 공식 배경/원문 표지로 번역 대상을 구분한다.
- 개인 사전 추가는 Mac 안의 파일을 만들고 자동 선택한다. 이름·문맥 헤더를 편집할 수 있다. 기존 파일은 유지하며 새 ID 집합을 저장한다. 구 일반/IT/내 용어집 설정도 이행하고 누락된 선택 파일은 ID를 보존하며 경고한다.
- 개인 용어는 같은 공개 용어보다 우선한다. 같은 우선순위에서 다른 번역이 있으면 제외하고 표시한다. 양방향과 띄어쓰기/하이픈 변형의 충돌을 처리한다.
- 직접 적은 오인식 표기만 교정한다. 서로 다른 개인 사전이 같은 별칭에 다른 목적지를 정하면 제외한다. 교정은 원래 입력에 한 번만 적용하므로 한 사전의 결과가 다른 사전으로 연쇄 치환되지 않는다.
- 개인 사전은 성공적으로 읽은 UTF-8 파일 32개, 파일당 256 KiB/300개 용어/용어당 8개 별칭으로 제한한다. 선택된 파일을 먼저 확보하므로 읽지 못하는 파일 때문에 선택이 밀려나지 않는다. 번역 대기 중에는 파일을 다시 읽지 않으며 미리보기는 개인 이름·내용을 읽지 않는다.

## 실시간 확인

단독 엔진 시간, 일정에 맞춘 원문 이벤트의 실제 Apple/로컬 번역·앱 상태 경로, 실시간 속도의 합성 음성·ASR 경로를 구분해 비교한다. 원문 이벤트 비교는 ASR·실제 화면 그리기·마이크 하드웨어를 포함하지 않으며, 파일 음성 비교도 실제 화자의 소음·발음이나 마이크 하드웨어를 포함하지 않는다. 각각의 raw 결과와 조건을 해당 비교 보고서에 남긴다.

실제 ASR를 포함한 동일 파일 8회 비교는 [ASR 파일 경로 보고서](dictionary-asr-realtime-20261002.md)에 있습니다. 빠른 자막의 대응 음성 구간 끝→상태 관찰 중앙값은 전체 표본에서 사전 없음 약 0.131초, 세 사전 약 0.130초로 뚜렷한 악화를 관찰하지 않았고 입력 누락은 0이었습니다. 이는 말하기 시작→최초 자막 시간이나 실제 화면 렌더 시간을 뜻하지 않습니다. 문장 최종 보완의 지연과 의미 오류는 별도로 기록합니다. 다음 초안과 보완의 동시 진행은 [원문 이벤트 비교](dictionary-realtime-20261002.md)에서 확인합니다.

수정된 계측 도구의 원문 이벤트 16회 비교도 완료했습니다. 세 사전/다듬기 켬에서 새 임시 원문→읽힌 번역 중앙값은 영어 93.1ms, 한국어 89.8ms였고, 같은 이벤트를 사전 없음과 짝지은 차이 중앙값은 영어 +0.4ms, 한국어 −1.5ms로 20ms 관찰 간격보다 작았습니다. 다듬기 확정은 영어 중앙값 163.7→246.9ms, 한국어 120.4→162.9ms로 늘었습니다. 영어 후보 2개는 출력 가드가 거부해 Apple 결과를 유지했으며, 약 1초의 보완 작업 중에도 다음 초안은 계속 읽혔습니다. 이 비교의 네이티브 시간 초과와 종료 후 남은 작업은 0이었습니다. 상세 조건과 기록 비용을 제거한 재측정은 [보고서](dictionary-realtime-20261002.md)에 있습니다.

## 최대 개인 사전의 CPU 준비 비용

실시간 검사 뒤 허용 최대 개인 구성도 별도로 검사했다. 음성/번역 모델을 호출하지 않는 합성 문자열 CPU 검사이며, 음성 인식·실제 화면·앱 전체의 지연을 나타내지 않는다.

- 32×300×8 = 76,800개 오인식 표기가 같은 `ordinary ...` 접두어를 갖고 248자 원문에는 `ordinary matters`만 있는 경우, 초기 접두어 후보 방식은 debug에서 원문 한 번 보정에 약 467ms 걸렸다. 압축 radix 인덱스로 고친 뒤 같은 shared-prefix 입력은 debug0.056~0.113ms, release(-O)0.012~0.034ms였다. 마지막 사전의 실제 별칭 교정은 release 약1.30ms였고 최장 구절/경계/원문 한 번 적용 회귀도 통과했다. 인덱스 생성은 대화 전 한 번 수행하며 release 약81ms였다. 합성 fixture와 Swift 런타임을 포함한 별도 검사 프로세스 최대RSS 약37MiB는 실제 앱 메모리 사용량을 뜻하지 않는다.
- 번역 참고용 32×300 = 9,600개 항목과 원문250자/별칭0으로 각 조건을5회 측정했다. 이전 구현은 매 항목 정규식과 원문 정규화를 수행해, 영어 release 프롬프트 준비만 중앙값 약3.8초 걸렸다. 모델 생성 전1.8초 논리 보완 시간이 소진될 수 있는 경로다. 실제 원문을 한 번 정규화하고 무관한 항목은 정규식 전에 제외하며8개를 찾으면 멈추도록 고쳤다.
