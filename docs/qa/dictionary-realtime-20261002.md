# 용어사전 선택의 실시간 번역 경로 비교 — 2026-10-02

## 검사 목적과 범위

용어사전 선택과 선택적 로컬 문장 다듬기가 다음 임시 자막의 빠른 Apple 번역을 늦추는지 비교한다. **실제 `CaptionModel.receive`에 시계에 맞춘 합성 원문 이벤트를 넣고 실제 Apple 번역과 실제 Hy-MT2를 실행한다. 음성 인식, 마이크 입력, 실제 UI 그리기 시간은 측정하지 않는다.** 합성 음성 파일을 실제로 인식하는 별도 검사와 구별해야 한다.

## 실행 방법

```sh
./scripts/check-dictionary-realtime.sh --build-only
./scripts/check-dictionary-realtime.sh --run-only --output docs/qa/raw/dictionary-realtime-20261002.json
```

기본값은 설치된 Hy-MT2-1.8B Q6_K와 기존 로컬 런타임을 사용한다. 모델이 없거나 파일명·고정 크기·스트리밍 SHA-256이 다르면 로딩 전에 중단한다. 모델이나 언어 자산을 내려받지 않는다. 다른 실제 모델 검사와 동시에 실행하지 않는다.

## 조건과 측정

- 방향: 영어→한국어와 한국어→영어를 명시적으로 선택한다.
- 조건: 다듬기 끔/사전 없음, 다듬기 끔/AI·IBM·금융권, 다듬기 켬/사전 없음, 다듬기 켬/AI·IBM·금융권.
- 반복: 각 방향에서 두 라운드를 실행하고 두 번째 라운드의 조건 순서를 뒤집는다. 총 16개 실행이다.
- 각 실행: 10초 동안 최종 원문 6개를 전달하며, 직전 최종 원문 이후 100/200ms에 다음 임시 원문을 전달한다. AI·IBM·금융권 표현, 숫자와 부정 표현, 일상적인 `recall`을 포함한다. 음성 인식 속도나 실제 분당 단어 수를 흉내 낸 값으로 제시하지 않는다.
- Apple: 설치 상태를 먼저 확인하고, 실제 저지연 번역 lease를 방향마다 준비·워밍업한 뒤 해당 방향의 조건들에 재사용한다.
- 로컬 모델: 무결성을 확인한 단일 엔진을 준비·워밍업하고 차례로 실행한다. 실제 기본 제한인 네이티브 1,500ms와 앱 다듬기 1,800ms를 사용한다.
- 문맥 묶음 보정은 꺼서 확정 문장 다듬기 경로를 분리한다. 환경설정은 별도 suite, 개인 사전은 빈 임시 폴더를 사용한다. 문맥 설정 setter가 쓰는 공용 설정은 즉시 원래 값으로 복원한다.
- 20ms마다 상태를 관찰하고, 원문 이벤트의 실제 도착부터 **그 원문과 일치하는 실제 Apple 번역이 처음 보인 시간**, 실제 번역이 처음 읽힌 시간, 화면 상태가 최종으로 바뀐 시간을 기록한다. 예전 원문의 회색 번역은 새 원문의 읽힌 시간으로 계산하지 않는다.
- 같은 원문의 임시 번역이 이미 보인 뒤 최종 이벤트가 오면 빠른 번역은 즉시 재사용될 수 있다. 그래서 최종 이벤트→빠른 번역 지연은 0에 가까울 수 있으며, 새로운 임시 원문→읽힌 번역 지연도 함께 검토한다.
- 앞 문장이 실제로 다듬어지는 동안 도착했거나, 새 번역이 보이기 전에 앞 문장 다듬기와 겹친 임시 원문을 별도로 기록한다. 새 수정으로 사라진 임시 원문은 측정되지 않은 것으로 남긴다.
- 관찰은 계속하지만 결과 파일에는 바뀐 상태와 원문 전달·정지 상태만 저장한다. 반복 관찰 수, 대기열 최대값과 불변식은 모든 관찰에서 계산한다.

2,500ms 입력→읽힌 번역 제한과 12초 정지·물리 작업 종료 제한은 심각한 멈춤을 검출하는 **실패 기준**이다. 실시간 체감 목표나 측정된 지연으로 제시하지 않는다. 체크 통과 여부와 실제 중앙값·상위 지연·조건 차이는 별도로 해석한다.

## 상태 검사

확정 자막의 원문·번역 버전이 일치하는지, 다음 입력 뒤 이미 확정된 자막이 바뀌지 않는지, 개인 교정이 없는 이 검사에서 원문이 그대로 남는지 확인한다. 로컬 호출 동시 실행은 1개로 제한되어야 한다. 빠른 번역 대기열과 화면에서 보이는 다듬기 대기 최종 번역 수를 관찰한다. 비공개 내부 다듬기 대기열을 반영한 값이라고 주장하지 않는다.

성공한 로컬 호출, 네이티브 타임아웃, 출력 가드 거부, 취소, busy 거부, 실제 로컬 결과와 일치하는 최종 번역 수를 기록한다. 다듬기를 켰지만 로컬 호출을 받지 않고 빠른 번역으로 끝난 원문 수와 밀린 문장을 건너뛴 안내문 관찰 여부도 남긴다. 이는 대기열 건너뛰기와 오류 후 다듬기 중단을 구분 없이 성공으로 취급하지 않기 위한 기록이다.

정지 후 논리 작업과 물리 번역 호출이 모두 끝났는지 확인하고, 200ms 뒤 늦은 결과로 자막이 다시 바뀌지 않는지 관찰한다. 물리 작업이 남으면 다음 비교 실행을 시작하지 않는다.

## 다듬기 실패와 대기 상태

48개 로컬 호출 중 46개가 완료됐고 출력 가드를 통과했다. 영어→한국어에서 사전 세 개를 선택했을 때 `IBM watsonx.ai supports generative AI.`가 두 라운드 모두 `unsafeOutput`으로 거부됐다. 해당 호출의 실제 경과 시간은 1,034.3ms와 1,016.8ms였다. 실제 프로덕션 출력 가드가 거부 후보의 텍스트·통계를 반환하지 않으므로, **후보를 복구할 수 없고 정확한 거부 원인은 알 수 없다.** 가드 거부를 의미 오류나 특정 언어 혼입으로 단정하지 않는다.

거부된 문장의 Apple 번역은 각각 50.3ms와 43.9ms에 먼저 읽혔고, 같은 번역을 유지한 채 최종 상태가 됐다. 해당 로컬 호출이 실제로 진행 중일 때 다음 `Assess credit risk`와 그 수정 원문의 Apple 번역도 관찰됐다. 네 이벤트의 지연은 80.8ms, 100.2ms, 82.3ms, 111.0ms였다. 다듬기 완료를 기다려 다음 빠른 번역이 멈춘 결과는 없었다.

네이티브 타임아웃, busy 거부, 로컬 취소, 다듬기를 켰지만 로컬 호출 없이 끝난 최종 원문은 모두 0개였다. 밀린 다듬기를 건너뛴 안내문은 관찰되지 않았다. 빠른 번역 대기열 최대는 1개, 보이는 다듬기 대기 최종 번역은 최대 1개, 실제 로컬 동시 호출은 최대 1개였다. 따라서 이 실행은 다듬기 대기열이 꽉 차서 건너뛰는 경우를 직접 재현하지 않는다.

총 입력은 256개, 관찰은 7,171회, 보존한 상태 변경·이벤트 스냅샷은 682개다. 160개 임시 이벤트 중 12개는 새 수정에 합쳐지거나 읽힌 상태가 관찰되기 전에 바뀌었다. 이를 입력 유실이나 번역 성공으로 계산하지 않으며, 모든 96개 최종 이벤트에는 읽힌 번역과 최종 상태가 남았다. 원문은 최종 문장 목록과 정확히 일치했고 이미 확정된 자막의 재작성은 없었다. 물리 호출과 스케줄러가 남지 않았으며 정지·물리 작업 종료의 최대 경과 시간은 217.7ms였다. 200ms 뒤에도 자막은 그대로였다.

## 측정 도구 수정 기록

첫 비교는 진단용 프롬프트·참고 용어 문자열을 MainActor에서 각 호출 전에 만들었다. 별도 CPU 검사에서 이 작업이 사전 세 개 기준 약 46~48ms 걸리는 것을 확인했다. 이 진단 작업은 프로덕션의 빠른 화면 경로에 없는 비용이므로, **측정이 끝난 뒤에 기록용 문자열을 만드는 방식으로 고치고 16개 조건을 전부 다시 실행했다.** 위 표와 결론은 다시 실행한 값만 사용한다. 이전 값은 [진단 비용이 섞인 별도 원시 파일](raw/dictionary-realtime-20261002-instrumented-prompt.json)에 한계를 명시해 보존한다.

## 해석의 한계

짧은 공개 합성 원문과 두 라운드만 비교한다. 새로운 화자, 긴 회의, 실제 말속도, 마이크 인식 지연, 시스템 오디오, UI 렌더링, 문맥 묶음 보정을 켠 전체 사용을 대표하지 않는다. 20ms 관찰 간격과 조건 순서·캐시·열 상태도 지연에 영향을 줄 수 있다. 번역 가드와 상태 검사는 용어 정확성이나 의미 보존을 증명하지 않는다.
