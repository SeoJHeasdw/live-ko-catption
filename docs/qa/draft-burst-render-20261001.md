# 초안 번역 대기와 화면 갱신 대기 줄이기 — 2026-10-01

대상은 0.4.5 (13) 커밋 `6ff212f`와 0.4.6 (14) 커밋 `de22568`입니다. 영어→한국어 실시간 자막의 지연 원인을 단계별로 나눠 보고, 코드에 있던 고정 대기 두 곳을 줄였습니다. Apple 음성 인식·번역 엔진, 오디오 콜백, 확정 조건과 문맥·보완 정책은 바꾸지 않았습니다.

모든 수치는 공개 합성 예문을 Samantha 음성 235wpm으로 만든 약 10.85초 파일을 이 Mac(M4 Max, macOS 26.7)에서 실행한 결과입니다. 실제 마이크·화자의 지연이나 정확도로 일반화하지 않습니다.

## 지연이 생기는 곳

| 단계 | 변경 전 | 변경 후 | 근거 |
|---|---|---|---|
| 음성 인식 결과 간격 | 약 0.9~1.0초마다 묶음 | 같음 | [인식 간격 측정](raw/asr-cadence-probe-20261001.txt) |
| 묶음의 최신 원문 → 번역 완료 | 중앙값 235ms, 최대 587ms | 중앙값 약 92ms, 최대 약 100ms | 파일 연결 검사 |
| Apple 번역 호출 | 11~45ms | 같음 | 파일 연결 검사 |
| 번역 완료 → 화면 갱신 예약 | 고정 100ms | 0~33ms | 코드, 직접 측정하지 않음 |

음성 인식기는 여러 수정본을 1~5ms 안에 한꺼번에 전달한 뒤 약 1초 동안 조용합니다. 이전 코드는 묶음의 첫 수정본을 바로 번역하고, 가장 최신 수정본은 550ms 초안 간격을 기다렸습니다. 묶음의 절반가량에서 최신 원문의 번역이 약 0.58초 늦었습니다.

## 변경

- **초안 번역 대기.** 원문 갱신이 50ms 동안 멈추면 그때의 최신 수정본만 번역합니다. 갱신이 끊이지 않아도 대기 초안은 150ms 안에 번역을 시작합니다. 고정 550ms 초안 간격은 제거했습니다. 확정 원문은 이전처럼 초안 대기를 건너뛰고 먼저 처리합니다.
- **화면 갱신.** 상세·간략 자막의 네이티브 갱신은 직전 갱신에서 1/30초가 지났으면 다음 실행 차례에 바로 그립니다. 그 안에 연속으로 오는 갱신은 최신 내용 하나로 묶습니다. 상세 화면의 최신 따라가기 스크롤 간격 0.2초는 유지합니다.

## 파일 연결 검사

`check-realtime-pipeline.sh`로 같은 파일을 100ms씩 실제 시간에 맞춰 공급해 로컬 영어 인식 → 제품 상태·큐 → 로컬 Apple 한국어 번역 → 정지를 실행했습니다. 변경 전 값은 기존 [0.4.4 결과](raw/fast-english-after-20261001.json)를 다시 분석한 것이고, 변경 후는 두 번 실행했습니다.

| 관측 | 변경 전 | 변경 후 1 | 변경 후 2 |
|---|---:|---:|---:|
| 인식 결과 묶음 | 13 | 13 | 13 |
| 초안·확정 번역 호출 | 19 | 13 | 13 |
| 묶음의 최신 원문 → 번역 완료, 중앙값 | 235ms | 93ms | 91ms |
| 같은 값, 최대 | 587ms | 102ms | 100ms |
| 현재 원문과 일치하는 번역의 음성 구간 끝 대비 지연, 중앙값 | 599ms | 123ms | 127ms |
| 같은 값, 최대 | 929ms | 934ms | 936ms |
| 누락 입력 버퍼 | 0 | 0 | 0 |
| 확정 원문 구절 | 3 | 3 | 3 |

세 실행의 확정 한국어 문장은 모두 같았습니다. 최대 지연이 줄지 않은 것은 확정 결과가 문장 끝에서 0.5~0.9초 뒤에 도착하는 인식기의 동작 때문이며, 이번 변경의 대상이 아닙니다.

"묶음"은 50ms 안에 이어 도착한 인식 결과이고, 측정값은 묶음의 마지막 결과가 도착한 뒤 정확히 그 원문의 Apple 번역이 끝날 때까지의 시간입니다. 화면 그리기는 포함하지 않습니다.

## 상태와 화면 검사

| 검사 | 결과 |
|---|---|
| `./scripts/build-app.sh` | 릴리스 앱 구성 통과 |
| `swift run --build-system native CaptionCoreChecks` | 26개 통과 |
| `swift run --build-system native TranslationSchedulingChecks` | 7개 통과 |

| 35초 합성 화면 검사 (간략·사이드바) | 통과 |

추가한 모델 검사는 연속으로 온 초안 수정본 중 최신 것만 한 번 번역하는지, 갱신이 끊이지 않아도 번역이 굶지 않는지 확인합니다. 첫 번째 검사는 이전 `CaptionModel`에서 실패하는 것을 확인했습니다. 확정 원문이 초안 대기를 깨우는 기존 검사는 새 대기 시간에 맞춰 조정했습니다.

합성 화면 검사는 초당 약 32회 상태를 바꾸므로 측정한 실제 인식 간격보다 훨씬 자주 갱신합니다. 이 조건에서 CPU 중앙값은 19.1%→22.3%, 메인 스레드 최대 멈춤은 55ms→60ms였습니다. 화면에 실제로 그려지는 시점은 측정하지 않았으므로 100ms→0~33ms는 예약 시간의 설계 값입니다.

## 인식기 비교

지연에서 가장 큰 부분은 인식 결과 간격입니다. 같은 파일로 인식기 설정을 비교했습니다. 입력 조각 크기는 간격에 영향을 주지 않았습니다.

| 인식기 | 결과 간격 중앙값 | 첫 결과 | 확정 결과 |
|---|---:|---:|---:|
| `SpeechTranscriber` + `.fastResults`, 100ms 입력 (현재) | 0.90초 | 1.13초 | 3 |
| 같은 설정, 20ms 입력 | 0.96초 | 1.11초 | 3 |
| `SpeechTranscriber`, `.fastResults` 없음 | 2.98초 | 4.03초 | 3 |
| `DictationTranscriber` + `.frequentFinalization` | 0.22초 | 0.63초 | 1 |

`DictationTranscriber`는 결과를 훨씬 자주 주지만 쉼 없는 발화에서 확정이 끝에 한 번만 나왔고 쉼표 하나가 빠졌습니다. 현재의 확정 원문 구조에 그대로 넣을 수 없으며, 실제 화자에서의 정확도는 확인하지 않았습니다. 이번 변경에는 포함하지 않았습니다.

```sh
say -v Samantha -r 235 -f docs/qa/raw/fast-english-fixture-20261001.txt -o /tmp/fast-english.aiff
./scripts/check-realtime-pipeline.sh /tmp/fast-english.aiff --output /tmp/fast-english.json
./scripts/check-ui-soak.sh 35 /tmp/render-interval-ui.jsonl --ui-soak-compact --ui-soak-sidebar
xcrun swiftc -swift-version 6 -target arm64-apple-macos26.4 -parse-as-library -O \
  Tests/AsrCadenceProbe/AsrCadenceProbe.swift -o /tmp/asr-cadence-probe
/tmp/asr-cadence-probe /tmp/fast-english.aiff speech-fast 100
```

인식 간격 도구는 `speech-fast`, `speech`, `dictation` 모드와 입력 조각 크기(ms)를 받습니다. 마이크를 열거나 언어 자산을 내려받지 않습니다.
