2026-09-30 영어→한국어 자막 적대적 번역 점검

실제로 준비된 Apple 로컬 번역 엔진에 20개 영어 입력을 넣고, lowLatency와
highFidelity 각각의 결과 40개를 비교했다. 결과와 호출 시간은 같은 폴더의
2026-09-30-translation-quality.json에 있다. 음성 인식·마이크·장시간 실행·네트워크
차단을 시험한 자료가 아니며, 텍스트 호출 시간을 실시간 자막 지연으로 읽으면 안 된다.
모든 전략 쌍의 한국어 출력이 같았다. Apple 문서는 highFidelity가 Apple Intelligence를
사용할 수 없을 때 기존 모델로 돌아갈 수 있다고 설명하므로 실제 엔진을 식별하거나
더 자연스러운 번역이 제공됐다고 판단할 근거는 없다.

실 사용 판정: 쉬운 영어 발화를 따라가는 보조 자막으로는 활용 가능성이 있지만,
자연스러운 통역이나 의미가 검증된 자막으로 신뢰하기에는 아직 부족하다.
진한 글씨는 현재 확정 원문의 번역을 받았다는 뜻일 뿐, 의미가 맞다는 증거가 아니다.

좋았던 결과:
- 단순 부정과 이중 부정의 방향, 조건부 생산 감축과 공장 폐쇄 미결정은 보존됐다.
- thirteen million과 thirty million, 0.5%와 5%, 1,200유로와 12,000유로는 구별됐다.
- break the ice, get the ball rolling, table the discussion, couldn't make it은
  대체로 관용적 의미를 전달했다. 일부 한국어 어순과 표현은 번역투였다.
- 미완성 'The proposal is not'는 '제안은 아닙니다'였지만, 이어지는
  'only cheaper but also safer'를 함께 번역하면 더 저렴하고 더 안전하다는 뜻으로
  바뀌었다. 인접한 최근 구절을 제한적으로 묶어 재번역하는 개선의 실제 근거다.

실패한 결과와 사용자에게 미치는 영향:
- duck_action_context: 'I saw her duck. She bent down to avoid the ball.'을 함께
  번역해도 '그녀의 오리'가 남았다. 후속 문맥만 더해도 다의어가 반드시 교정되지는 않는다.
- cake_food: 냉장고와 프로스팅 문맥을 더해도 케이크 조각이 '식은 죽 먹기'로 남았다.
  관용 표현이 실제 사물을 뜻하는 상황에서 확신에 찬 오역이 가능하다.
- self_correction: 목요일→화요일 정정은 포함됐지만, 원문에 없는 '오후'를
  3시 15분에 추가했다. 시간을 표시할 때 없던 조건을 만들어 낼 수 있다.
- technical: recall과 precision을 '리콜'과 '정확도'로 번역해 재현율·정밀도의
  구별을 잃었다. 'below 0.05'도 '0.05 이하'로 바뀌어 미만과 이하의 경계가 달라졌다.
- currency_names: 'Ask Dr. Lee ...'가 '의사에게 물어보세요. Lee, ...'로 분리됐다.
  숫자가 맞더라도 고유명사와 호칭의 연결이 깨질 수 있다.

이 점검에서 할 수 있는 개선은 원문과 번역의 버전을 정확히 맞추고, 실패를 드러내며,
미완성·인접한 구절을 제한된 문맥으로 다시 번역하는 것이다. 특정 단어나 부정을
규칙으로 바꿔 쓰면 새로운 오역을 만들 수 있어 자동 치환은 하지 않았다.
원문 함께 보기를 기본으로 유지하고, 실패한 자막은 설정과 관계없이 원문을 표시한다.

실제 사용 가능 여부를 결정하기 전에 필요한 검증:
- 목표 핀마이크와 영어 화자 한 명으로 20~30분 이상 실행하며 읽을 만한 첫 자막과
  최신 수정 자막의 지연, 번역 대기 누적, 회색→진한 표시를 영상·기준 대본으로 확인한다.
- 문장 중간의 부정·not only, 요일 정정, 금액·소수·백분율·단위, 이름과 전문 용어를
  기준 대본과 대조한다. 화면의 안정성 검사를 의미 정확성 검사와 구분한다.
- 실제 화자의 억양·발음·속도와 주변 소음에서 빠진 말과 잘못 들은 말을 점검한다.
  합성 음성 파일 결과를 실제 사람·마이크 정확도로 일반화하지 않는다.
- 일시정지·재시작, 마이크 분리·재연결, 모델 준비 후 네트워크를 끈 상태,
  오래된 문맥의 동결과 최근 문맥 수정, 기록 저장의 미확정 표시를 확인한다.

재현 명령:
swift run --build-system native LocalPipelineCheck --translation-quality --compare-strategies

추가된 실제 동시 처리 검증:
check-realtime-pipeline.sh는 음성 파일을 100ms 조각으로 실제 발화 속도에 맞춰
AudioPump에 보낸다. 실제 SpeechAnalyzer 결과가 들어오는 동안 제품의 CaptionModel
대기열과 문맥 보정을 실행하고, 각 번역에는 실제 로컬 TranslationSession을 사용한다.
마이크를 열거나 언어 모델을 다운로드하지 않는다. 상태 관찰 간격은 20ms이며 화면
렌더링 시간과 마이크 하드웨어 지연은 측정하지 않는다.

15.63초 Samantha 합성 음성의 최종 검증에서 64개 중간 인식 결과와 6개 확정 원문을
받았다. 모든 확정 원문이 정확히 남았고, 원문·번역 버전 불일치의 확정 표시와 음성
버퍼 누락은 없었다. 실제 문맥 번역 4회와 진한 자막→회색 표시 4회를 관찰했다.
번역 대기는 최대 2개였으며 종료 후 제품 대기열과 실제 번역 호출이 모두 비었다.
첫 최신 버전 한국어 초안은 파일 전송 시작 후 약 1.70초, 대응 음성 구간 끝으로부터
약 0.60초 뒤에 관찰됐다. 현재 원문과 정확히 대응하는 번역 18개 갱신의 지연 중앙값은
약 0.60초, 최대는 약 1.14초였다. 낡은 번역과 문맥 확인 중인 번역은 통계에서 제외했다.
이는 짧은 합성 음성의 모델 상태 관찰 결과이며 실제 마이크 지연으로 일반화할 수 없다.

이 검증으로 문맥 묶음의 결함도 드러났다. 처음에는 3개 구절 뒤에 묶음을 동결해,
세 번째 구절의 Tuesday 정정 예고와 네 번째 구절의 Thursday가 다른 묶음에 남았다.
12초·500자 제한을 유지하며 최대 4개 구절까지 묶도록 수정한 뒤 같은 실제 파일을
다시 검증했고, 정정되는 네 번째 구절도 하나의 묶음에 포함됐다. 이전 결과는
2026-09-30-realtime-pipeline-before-context-boundary.json에, 수정 후 결과는
2026-09-30-realtime-pipeline.json에 있다.

의미 판정은 제한적이다. 실제 번역 엔진은 기존 '출시가 화요일인 줄 알았는데,
정정하겠습니다.'를 새롭게 고쳐 쓰지 않고 '10월 15일 목요일입니다.'를 같은 묶음에
추가했다. 문맥의 포함과 회색 재번역은 확인됐지만, 앞 문장의 잘못된 의미가 언제나
자동 교정된다는 증거는 아니다. 4개 구절·12초·500자를 넘는 오래된 문맥은 다시
번역하지 않으므로 늦게 드러나는 의미 반전에는 여전히 한계가 있다.
