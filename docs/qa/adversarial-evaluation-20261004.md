# 2026년 10월 4일 적대적 평가

현재 코드에서 우선 수정할 결함 8개를 재현했습니다. 가장 큰 문제는 시스템 오디오 장치를 여는 동안 메인 스레드가 멈추는 현상입니다. 번역 상태와 취소 방어는 광범위한 검사를 통과했지만, 의미가 달라진 번역도 최종 자막으로 표시될 수 있었습니다.

이번 평가는 코드 리뷰, 기존 검사군 전체 실행, 별도 경계 재현, 무작위 상태 검사, 실제 설치된 Apple 엔진과 Hy-MT2 모델의 공개 합성 예문을 포함합니다. 앱의 정상 입력 경로에서 확인한 결함과 비정상 파일·SDK 입력을 전제로 한 강화 후보를 구분했습니다. 가능한 조건을 모두 증명하는 완전한 검증이나 실제 화자의 정확도 평가로 해석할 수는 없습니다.

## 대상과 실행 조건

- 날짜: 2026년 10월 4일, 한국 시간.
- 기준 소스: `9452aa29164c0b1094b01a8e056112bcc922f8a4`, main.
- 실행 환경: Apple Silicon, macOS 26.7.1 build 25G241, Apple Swift 6.4.
- 앱과 런타임의 배포 대상: macOS 26.4. 생성 앱의 최소 버전과 임시 서명을 확인했습니다.
- 모델: Hy-MT2-1.8B Q6_K, 1,474,785,120바이트. 실행 전 전체 SHA-256이 고정값 `d98fe604dec1f28f58f80d7d560f7177e584d3b8e5835862687660e5ff97cb40`과 일치했습니다.
- 실제 사람의 마이크나 개인 사전 내용을 fixture로 사용하지 않았습니다. 합성 오디오와 공개 문장만 평가 원자료로 보관했습니다.
- 생산 코드와 기존 검사 소스는 수정하지 않았습니다. 보고서, 원자료, 재현 도구를 추가했습니다. 기존 `.vscode/` 작업물은 평가 변경에 포함하지 않았습니다.

[실행 요약과 소스별 SHA-256](raw/adversarial-20261004/summary.json)에 대상 식별을 남겼습니다. 이전 QA의 성공을 이번 실행의 성공으로 대신하지 않았습니다.

## 우선 수정할 결함

P1은 앱 전체의 응답을 막는 문제, P2는 특정 입력·조작 조건에서 기능이나 입력 보존을 깨뜨리는 문제로 사용했습니다. 우선순위는 이번 평가의 판단이며, 발생 빈도를 측정한 등급은 아닙니다.

| 우선순위 | 문제 | 재현 결과 |
|---|---|---|
| P1 | 시스템 오디오 시작이 메인 스레드를 막음 | 실제 장치 선택 호출이 100초 넘게 HAL IPC에 대기 |
| P2 | 무음 타이머가 오디오 시간축을 손실 | 10초의 타이머 입력이 분석기 오디오 5초로 축소 |
| P2 | 실제 입력과 합성 무음의 제출 순서 경쟁 | 먼저 도착한 버퍼가 뒤 버퍼보다 늦게 전달 |
| P2 | 방향 전환 중 재개를 허용 | 방향 전환 요청이 사라지고 이전 언어로 시작 |
| P2 | 모델 검증 캐시가 변조 파일을 승인 | 같은 크기·inode·mtime의 변경 파일을 재해시하지 않음 |
| P2 | 개인 사전의 결합 문자가 원문 크기를 증폭 | 599바이트 원문이 2,000,199바이트로 증가 |
| P2 | 개인 사전 NUL이 네이티브 프롬프트를 절단 | 실제 원문을 포함한 뒤쪽 프롬프트가 C 경계에서 사라짐 |
| P2 | 모델 제어 토큰이 입력 내용으로 격리되지 않음 | 특수 토큰 뒤 입력을 누락한 후보가 guard 통과 |

### 시스템 오디오 시작 중 앱 응답 중단

[AudioCapture.swift](../../Sources/LiveKoCaption/AudioCapture.swift)의 437행에서 MainActor가 동기적으로 장치를 만듭니다. 실제 `check-system-audio.sh` 실행은 [AudioDeviceCapture.swift](../../Sources/LiveKoCaption/AudioDeviceCapture.swift) 49–50행의 `AudioUnitSetProperty(CurrentDevice)`에서 100초 넘게 멈췄습니다. 스택 샘플과 호출 오프셋이 이 위치에 일치했습니다. 실행을 종료했으며 이 검사 결과는 실패로 기록했습니다.

앱도 같은 생성 경로를 [CaptionModel.swift](../../Sources/LiveKoCaption/CaptionModel.swift) 666행에서 호출합니다. 따라서 이 조건에서는 시작 취소·중지·종료 UI와 MainActor의 시간 제한이 함께 실행되지 못합니다. watchdog의 장치 설정 조회도 메인 스레드에서 동기 HAL 호출을 합니다.

장치 생성·시작·설정 조회를 전용 제어 큐에서 처리하고, 취소 이후 늦게 성공한 시작 자원을 실행 토큰으로 확인해 정리하는 방향이 필요합니다. 단순히 MainActor의 시간 제한으로 감싸는 것은 동기 정지를 해결하지 못합니다.

증거: [멈춘 호출 스택](raw/adversarial-20261004/system-audio-stall.txt). 전체 출력 탭과 권한 창을 시험한 결과는 아닙니다. 합성 재생 프로세스 하나를 탭한 이번 환경의 재현입니다.

### 무음 구간 시간 손실과 오디오 제출 순서

`AudioPump.enqueueSilenceIfIdle`은 직전 입력과 실제로 100ms 이상 떨어져야 무음을 넣습니다. [AudioCapture.swift](../../Sources/LiveKoCaption/AudioCapture.swift) 173행의 이 조건은 100ms 타이머의 미세한 지터에 따라 틱을 건너뜁니다.

1μs의 교대 지터를 준 100틱·10초 검사에서 분석기로 80,000프레임, 즉 16kHz 기준 5초만 전달됐습니다. 실제 production timer도 첫 실행에서 벽시계 3.208초 동안 오디오 2.3초만 만들었고, 재현 도구 재실행에서는 3.209초 동안 2.5초를 만들었습니다. 실제 지터에 따른 손실 크기는 달라도 결함은 반복됐습니다. 조용한 구간 뒤 자막 시간이 뒤처지고, 이를 이용한 ASR 지연 표시도 부풀 수 있습니다.

별도로 210–217행은 예약 잠금을 풀고 버퍼를 복사한 뒤 변환 큐에 제출합니다. 두 생산자가 겹치면 복사 완료 순서가 전달 순서가 됩니다. 첫 복사만 지연한 검사에서 입력 `[+1000, -1000]`이 분석기에 `[-1000, +1000]`으로 전달됐습니다. 시스템 오디오의 실제 콜백과 무음 타이머가 다른 스레드에서 같은 pump를 호출하므로 적용 가능한 경쟁입니다. 실제 재생에서의 발생 빈도는 측정하지 않았습니다.

무음은 경과 시간의 누적을 기준으로 보충하고, 실제 입력과 무음을 시간 순서대로 제출해야 합니다. [IdleAudit.swift](repro/adversarial-20261004/IdleAudit.swift)와 [OrderAudit.swift](repro/adversarial-20261004/OrderAudit.swift)에 재현을 보관했습니다.

### 방향 전환과 자막 재개 경쟁

[CaptionModel.swift](../../Sources/LiveKoCaption/CaptionModel.swift) 251행의 `canStart`는 `isSwitchingDirection`을 검사하지 않습니다. 일시정지한 대화에서 방향 전환을 누르고, 다른 언어의 설치 확인이 끝나기 전에 재개나 Space를 누르면 이전 언어로 시작할 수 있습니다. 설치 확인이 시작 준비 중 끝나면 530행의 guard에서 전환이 아무 알림 없이 사라집니다. 상세 창·간략 창·메뉴에도 추가 차단이 없습니다.

설치 확인을 의도적으로 보류한 재현에서 `switching=true, canStart=true`였고, 마이크 접근 요청이 이전 영어 방향으로 한 번 발생했습니다. 확인을 해제해도 영어→한국어 방향이 그대로 남았습니다. 실제 마이크는 열지 않고 주입한 권한 응답을 사용했습니다.

방향 전환 중 시작과 관련 설정 변경의 입장을 직렬화해야 합니다. [DirectionAudit.swift](repro/adversarial-20261004/DirectionAudit.swift)에 재현을 보관했습니다.

### 모델 digest 캐시 우회

[LocalModelStore.swift](../../Sources/LiveKoCaption/LocalModelStore.swift) 163–165행은 파일 크기·수정 시간·inode가 캐시와 같으면 SHA-256을 생략합니다. 작은 임시 fixture를 `abc`로 검증한 뒤 같은 inode에 `def`를 쓰고 원래 mtime을 복원하자, 다시 읽어도 `isInstalled=true`이고 `modelURL`이 노출됐습니다.

로컬 모델 파일에 쓸 권한이 있어야 하는 조건입니다. 원격 변조 가능성을 입증한 결과는 아닙니다. 다만 모델을 로드하기 전 고정 digest를 확인한다는 프로젝트 불변식을 현재 캐시가 충분히 보장하지 못합니다. 실제 로드 전 검증을 강화하고 같은 크기·mtime의 변경 파일을 회귀 검사에 넣어야 합니다.

[ModelCacheAudit.swift](repro/adversarial-20261004/ModelCacheAudit.swift)는 실제 GGUF를 건드리지 않는 3바이트 재현입니다.

### 개인 사전의 Unicode 증폭과 NUL

[Glossary.swift](../../Sources/CaptionCore/Glossary.swift) 76행은 용어 길이를 확장 grapheme 수인 `String.count`로만 제한합니다. `A + U+0301 × 10000`은 10,001 Unicode scalar지만 문자 수는 1이므로 통과합니다. 파일 크기 제한 안의 20,019바이트 사전 한 항목으로, 별칭이 100번 등장하는 599바이트 원문이 2,000,199바이트로 증가했습니다. 늘어난 원문도 로컬 요청의 1,000문자 제한을 통과했습니다.

개인 교정 결과는 [CaptionModel.swift](../../Sources/LiveKoCaption/CaptionModel.swift) 918–927행에서 바로 timeline에 들어가고 Apple 번역·화면·저장 경로에 전달됩니다. optional runtime의 별도 바이트 제한은 그 전에 생긴 문자열 증폭을 막지 못합니다. 실제 Apple 엔진의 추가 메모리·지연 영향은 시험하지 않았습니다.

또한 사전 `# 문맥:`에 NUL이 있으면 [GlossaryDictionaries.swift](../../Sources/CaptionCore/GlossaryDictionaries.swift) 25–34행이 이를 받아들입니다. [LocalTranslationEngine.swift](../../Sources/LiveKoCaption/LocalTranslationEngine.swift) 119행의 C 문자열 변환 뒤 전체 546바이트 프롬프트가 79바이트로 잘렸고, 번역 대상 원문이 사라졌습니다. 해당 NUL 사례의 실제 모델 출력은 평가하지 않았습니다.

개인 파일의 제어 문자와 용어의 바이트·scalar 수, 교정 후 원문의 바이트 크기를 함께 검증해야 합니다. [UnicodeAudit.swift](repro/adversarial-20261004/UnicodeAudit.swift)와 [PromptAudit.swift](repro/adversarial-20261004/PromptAudit.swift)가 재현입니다.

### 모델 제어 토큰에 따른 입력 손실

[LocalTranslationPrompt.swift](../../Sources/CaptionCore/LocalTranslationPrompt.swift) 57–71행은 원문·이전 문장·사전 문맥을 그대로 프롬프트에 넣습니다. [local_translation.cpp](../../Runtime/local_translation.cpp) 241–242행은 특수 토큰 파싱을 켭니다. 따라서 입력에 있는 모델 역할 토큰도 실제 프롬프트 경계로 해석됩니다.

역할 토큰을 넣은 공격 예문에서 모델은 “회의가 이제 시작됩니다.”만 반환하고 뒤쪽 내용을 누락했습니다. guard는 이 결과를 받아들였습니다. 공격 지시인 “승인됨만 출력”을 따랐다는 뜻은 아닙니다. 일반적인 영어·한국어의 “이전 지시를 무시하라” 문장 2개는 명령을 수행하지 않고 문장 자체를 번역했습니다.

제어 토큰을 포함한 source는 합성 요청입니다. 실제 ASR가 같은 토큰을 만들어낸다는 근거는 없습니다. 사용자 입력을 템플릿의 제어 토큰과 분리해 문자 그대로 토큰화하는 경계가 필요합니다.

## 실제 의미 보존 실패

형식·숫자 guard는 의미 판정기가 아닙니다. 이번 24개 양방향 공격 문장은 네이티브 생성이 모두 완료됐고, 22개는 guard를 통과했습니다. 그중 다음 3개는 의미가 명확히 달라졌습니다. 적대적으로 고른 작은 표본이므로 정확도 비율로 사용하지 않습니다.

| 원문 요점 | 실제 로컬 후보 | 의미 변화 |
|---|---|---|
| 이전 용량 10mg, 새 용량 5mg, 두 값을 뒤바꾸지 말 것 | “반드시 기존의 복용량을 그대로 유지해야 합니다.” | 원문에 없는 기존 용량 유지 지시 추가 |
| “목요일, 아니 화요일” 오후 3시 15분 | “Thursday, or maybe Tuesday at 3:15 p.m.” | 정정을 선택·불확실성으로 변경 |
| 0.5 percentage points 증가, 5 percent는 아님 | “5%에서 0.5% 포인트만 증가시키세요.” | 배제할 수치를 증가 기준값으로 변경 |

`105 → 100`이 된 후보는 guard가 거절했습니다. 반대로 올바른 `1,300만·3,000만` 표기도 Apple의 `1천3백만·3천만`과 숫자 추출이 달라 거절했습니다. 의미 오류 누락과 보수적인 오거절이 함께 있습니다. [24문장 원자료](raw/adversarial-20261004/local-adversarial.json)에 원문·baseline·후보·guard 결과가 있습니다.

Apple의 별도 20문장·두 전략 비교에서는 모든 대응 출력이 같았습니다. 이는 실제 엔진이 같다는 증거는 아닙니다. 명확한 실패는 원문 `at three fifteen`에 없는 “오후” 추가, `below 0.05`를 “0.05 이하”로 변경, `precision`을 “정확도”로 번역한 사례입니다. 실제 케이크를 냉장고에 넣는 후속 문맥에서도 “식은 죽 먹기”, 공을 피해 숙이는 후속 문맥에서도 “그녀의 오리”라는 앞 해석이 유지됐습니다. 단독 중의 문장과 미완성 원문은 확정 오역으로 세지 않았습니다. [Apple 비교 원자료](raw/adversarial-20261004/apple-quality.json)에 전체 결과가 있습니다.

사전 비교의 30조건에서도 사전이 의미를 보장하지 않았습니다. IBM 제품을 사용한 **다음** 재해 복구 계획을 검토하자는 원문이 사전 없음·문맥만·문맥과 용어 모두에서 제품을 **이용해** 계획을 검토하자는 내용으로 바뀌었습니다. 다른 예문의 기술 적합성을 **평가하자**는 제안도 사전 없음·문맥과 용어 조건에서 기술을 **사용해** 문서를 검토하자는 내용으로 바뀌었습니다. 모두 guard를 통과했습니다. [사전 비교 원자료](raw/adversarial-20261004/dictionary-translation.json)를 참고하세요.

양방향 음성 통합의 한국어 IT 예문도 상태 검사는 통과했지만 내용은 실패했습니다. Yuna 합성 음성의 “배포”가 “제 포”, “느리면”이 “누리면”으로 확정 인식됐습니다. 최종 로컬 보완은 `My project is finished ... if the API response changes`로 추측해, 배포를 내 프로젝트로 바꾸고 되돌리기 조건인 느림을 변경으로 바꿨습니다. 이 결과는 guard를 통과하고 밝은 최종 자막이 됐습니다. [음성 통합 원자료](raw/adversarial-20261004/bidirectional.json)의 한국어 IT fixture에서 확인할 수 있습니다.

## 별도 강화 후보와 미검증 조건

직접 Core API를 사용한 다음 경계도 재현했습니다. 정상 앱 경로의 결함으로 동일하게 세지 않았습니다.

- 유한하지만 Int 범위를 넘는 타임스탬프를 받아들이면 `CaptionTimeline.exportText` 323행과 화면의 시간 변환에서 충돌할 수 있습니다. 비정상 SDK 입력을 전제로 한 재현의 내보내기 자식 프로세스는 signal 5로 종료했습니다.
- 같은 확정 job에 `apply`를 다시 호출하면 최종 번역을 바꿀 수 있습니다. 현재 생산 스케줄러에서 이 중복 호출의 도달성은 확인하지 못했습니다.
- 직접 `timeline.direction`만 바꾸면 양방향 자막을 하나의 문맥으로 묶을 수 있습니다. 정상 앱은 재개 시 `resetContext`로 방어합니다.
- `CaptionGlossary(entries:)`에 직접 10,000개를 넣을 수 있습니다. 현재 파일 파서는 300개 제한을 유지합니다.

합성 무음은 실제 콜백이 없어도 `hasReceivedInput=true, stalled=false`로 만듭니다. 시스템 오디오의 정상 무음과 입력 경로 무응답을 이 heartbeat만으로 구별할 수 없다는 검증 공백입니다. 실제 권한 거절·철회의 OS 동작은 시험하지 않았습니다.

마이크의 실제 화자·발음·잡음, 시스템 전체 출력의 권한 거절과 철회, 절전과 깨우기, 장치 분리와 재연결, 네트워크 차단, macOS 26.4 실기기, 새 30분 열화 검사는 이번에 수행하지 않았습니다. 현재 SDK의 번역 Strategy와 설치 언어 생성자의 macOS 26.4 가용성, 앱 최소 버전, 런타임의 Apple 시스템 라이브러리 의존성은 확인했습니다. 원본 오디오를 저장하거나 외부 추론 서비스를 사용하는 경로는 코드 리뷰에서 발견하지 못했으며, 네트워크 격리 실험을 대신하는 결과는 아닙니다.

## 재현과 수정 순서

새 재현 도구는 합성 PCM·임시 3바이트 모델·주입한 권한 응답을 사용합니다. 마이크나 실제 GGUF를 열거나 모델을 다운로드하지 않습니다.

```sh
./docs/qa/repro/adversarial-20261004/run.sh
```

실행할 때마다 `.build/adversarial-20261004.*`에 별도 출력 폴더를 만듭니다. 이 도구의 exit 0은 재현 프로그램 실행이 완료됐다는 뜻이며, 앱이 결함 검사를 통과했다는 뜻은 아닙니다. 의도적인 타임스탬프 충돌은 자식 프로세스에서만 실행합니다.

수정은 시스템 오디오의 메인 스레드 정지와 시간축부터, 방향 전환 직렬화, 개인 사전의 문자·크기 검증, 모델 로드 전 무결성, 프롬프트 입력 경계 순서로 진행하는 것이 좋습니다. 의미 보존 실패에는 실제 원문 대조 평가를 유지해야 하며, built-in 단어 치환으로 고치면 프로젝트의 원문 보존 정책을 위반합니다.
