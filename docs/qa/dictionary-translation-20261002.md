# 용어사전 실제 모델 비교 — 2026-10-02

## 비교 방법

`./scripts/check-dictionary-translation.sh`는 현재 `BuiltInDictionaries`를 사용해 공개된 용어로 작성한 합성 문장 10개(영어→한국어 5개, 한국어→영어 5개)를 같은 로컬 엔진에서 순차 번역한다. AI, IBM, 금융권 각각과 세 사전을 함께 사용하는 문장, 그리고 일상적 기억·관심 표현을 포함한다.

같은 원문을 다음 세 조건으로 비교한다.

1. 사전 없음
2. 선택한 분야 맥락만 사용: 같은 사전에서 용어 항목을 비운 복사본
3. 선택한 분야 맥락과 현재 문장에 일치하는 용어 항목 사용

기본 제한 시간은 문장당 6,000 ms이며 문장 품질 관찰을 위한 값이다. 앱의 1,500 ms 제한 충족이나 실제 자막 지연을 입증하지 않는다. 앞 문장, Apple 번역, 오디오, 개인 용어집을 사용하지 않고 앱 설정을 변경하지 않는다. 모델 다운로드도 수행하지 않는다.

러너는 `Resources/local-model-manifest.json`의 설치 경로·크기와 SHA-256(또는 manifest가 지정한 소스 상수)을 읽는다. 실제 설치 파일의 전체 SHA-256을 스트리밍 계산해 크기와 digest를 모두 확인한 다음 모델을 로드한다. 모델 또는 런타임이 없거나 확인에 실패하면 종료한다.

완료된 후보의 원문, 사전 이름, 프롬프트, 실제 전달된 용어쌍, 번역문, 출력 guard 결과, 네이티브 측정값을 [raw JSON](raw/dictionary-translation-20261002.json)에 저장한다. guard는 원문을 숫자 비교 기준으로 사용하며, 실제 앱의 Apple baseline에 대한 비교와 다르다. 출력 guard 통과는 형식·문자·숫자 검사 결과이고 정확도 점수가 아니다.

## 기존 raw의 실행시간 관찰

아래 값은 위의 최종 30개 결과를 읽어 계산했다. 추가 모델 실행은 하지 않았다. 각 조건은 같은 원문 10개를 사용한다. `native total`은 네이티브 생성의 총시간, `wall`은 Swift 호출부터 결과 guard·통계 수집까지의 시간이며, 모델 준비·파일 hash·오디오·ASR·Apple 번역·앱 스케줄링을 포함하지 않는다. 시간 단위는 ms다.

| 조건 | native total 중앙값 / 최대 | wall 중앙값 / 최대 | TTFT 중앙값 | 입력 / 출력 tokens 중앙값 | native / wall >1,500 ms |
| --- | --- | --- | --- | --- | --- |
| 사전 없음 | 194.9 / 320.8 | 195.3 / 321.2 | 29.7 | 47 / 26.5 | 0 / 0 |
| 분야 맥락만 | 200.1 / 306.4 | 200.4 / 306.9 | 48.8 | 111.5 / 23 | 0 / 0 |
| 분야+용어 | 213.5 / 337.9 | 223.6 / 350.0 | 65.2 | 133 / 23.5 | 0 / 0 |

각 원문에서 **분야+용어 − 사전 없음**의 차이를 먼저 계산한 paired 중앙값은 영어→한국어에서 native **+17.1 ms**, wall **+28.8 ms**, TTFT **+20.4 ms**였고, 한국어→영어에서는 각각 **+37.9 ms**, **+38.1 ms**, **+39.3 ms**였다. 전체 10개 원문의 paired wall 차이는 중앙값 **+34.3 ms**, 최대 **+67.0 ms**였다. 분야+용어의 입력은 최대 180 tokens였다. 이 짧은 표본에서는 1,500 ms를 넘는 후보나 큰 추가 지연은 관찰되지 않았다.

이 결과를 제품의 실시간 성능으로 그대로 읽으면 안 된다. 각 조건은 1회이며 순서는 항상 사전 없음→분야 맥락만→분야+용어로 고정했고, 첫 사전 없음 예문은 별도 워밍업 없이 최초 생성이었다. 번역문 내용과 출력 길이도 달라 영어→한국어 일부 후보의 total이 줄었는데, 이를 사전 자체의 가속 효과로 볼 수 없다. TTFT 증가는 긴 입력 처리 비용과 더 직접적으로 관련된다. 분야+용어 조건에서 native 밖의 wall 차이는 최대 26.4 ms였으므로 프롬프트 구성·결과 처리 비용도 실제 호출시간에 포함해야 한다. 러너의 6,000 ms 제한에서 측정한 값이므로 **제품의 실제 1,500 ms timeout 동작이나 실시간 ASR·빠른 번역·로컬 보완의 동시 실행을 시험한 결과는 아니다**. 긴 원문·앞 문장·개인 사전·다른 시스템 부하에 대한 반복 측정도 없다.

검토할 항목은 다음과 같다.

- AI: 관련 문서를 모델에 제공한다는 의미가 학습·정확도 향상으로 바뀌지 않는지
- IBM: 제품명이 유지되고 “데모 사용 후 재해 복구 계획 검토”라는 순서와 제안 어조가 유지되는지
- 금융권: AML·신용위험·LCR이 구별되고 없는 규제 비율을 추가하지 않는지
- 복합 분야: 기술을 사용할지 평가한다는 의미가 이미 운영 중이라는 단정으로 바뀌지 않는지
- 일상 표현: `recall`을 재현율로, `interest`를 금리·이자로 바꾸지 않는지

이 합성 문장 비교는 탐색용이며 대표적인 금융권 번역 벤치마크, 실제 ASR 정확도 평가, 라이브 자막 성능 검증이 아니다.
