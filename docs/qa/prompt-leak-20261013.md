# 분야 설명이 자막으로 번역되어 나오던 문제 — 2026-10-13

대상: 0.5.2 (22)에서 발견, 0.5.3 (23)에서 수정. macOS 27.0.1, M4 Max, 설치된 Hy-MT2-1.8B Q6_K.

## 증상

문장 다듬기를 켜고 AI·IBM 사전을 선택한 실제 사용에서, 한국어 자막 자리에 다음 문장이 반복해서 나왔습니다.

```
[배경 정보]
AI, 머신러닝, 생성형 AI에 관련된 용어들. IBM의 엔터프라이즈 소프트웨어, 하이브리드 클라우드 및 인프라; IBM의 공식 제품명을 그대로 사용합니다.
```

이는 사전의 영어 분야 설명을 모델이 한국어로 번역한 것입니다. 원문의 번역은 들어 있지 않았습니다.

## 원인

0.5.2의 프롬프트는 분야 설명을 모델의 공식 `[Background Information]` … `[Source Text]` 형식에 넣었습니다. 이 형식은 [공식 README](https://github.com/Tencent-Hunyuan/Hy-MT2/blob/main/README.md)의 "Structured Data 2" 항목이며, 모델은 배경 블록과 라벨까지 번역해 돌려주도록 반응합니다. 공식 형식 그대로는 188개 중 187개 출력이 배경 블록을 함께 번역했습니다. 0.5.2는 뒤에 "원문만 번역하라"는 지시를 덧붙여 대부분 억제했지만 약 9%는 그대로 나왔습니다.

출력 검사는 `\n\n`이 있는 출력과 일부 영어 라벨만 거부했습니다. 모델이 배경 블록만 번역하고 끝낸 출력(위 증상)은 줄바꿈이 한 번뿐이고 라벨이 한국어 `[배경 정보]`여서 통과했습니다. 2026-10-02의 사전 비교는 30개 조건에서 유출을 보지 못해 "관찰되지 않았다"고 기록했습니다. 표본이 작았습니다.

## 수정

- 분야 설명을 블록으로 두지 않고 공식 번역 지시문 안의 한 구절로 넣습니다.
  `Translate the following text from a talk about <분야 설명; 분야 설명> into Korean. Note that you should only output the translated result without any additional explanation:` 뒤에 빈 줄과 원문이 옵니다. 용어 참고가 있으면 공식 용어 형식(`Reference the following translations:` …, `must ONLY`)을 앞에 둡니다.
- 내장 사전의 분야 설명을 이 구절에 맞는 명사구로 바꿨습니다. 합친 길이는 300자까지이며 설명 단위로만 넣습니다.
- 0.5.2가 덧붙였던 `Use natural subtitle phrasing…`, `Apply reference terms only when…`, `Translate ONLY [Source Text]…` 문장은 없앴습니다.
- 출력 검사: 원문에 줄바꿈이 없는데 출력에 줄바꿈이 있으면 거부, 원문에 없는 `[`·`【`가 있으면 거부, 길이 한도를 영어→한국어 `원문×2+20`자, 한국어→영어 `원문×5+30`자로 낮췄습니다(이전: 방향과 무관하게 `max(120, 원문×4)`).
- 이전 문장을 배경으로 넣는 경로(`previousSentence`)는 과거 QA 비교의 재현용으로만 남겼습니다. 앱은 이 값을 넣지 않습니다.

## 형식을 고른 근거

런타임을 직접 호출하는 임시 도구로 같은 입력에 여러 프롬프트 형식을 비교했습니다. 프롬프트는 그 도구가 조립했으며 제품 코드 경로가 아닙니다. 영어→한국어 188개 기준입니다.

| 형식 | 블록·라벨이 번역된 출력 | 지시문 문장이 섞인 출력 |
| --- | ---: | ---: |
| 0.5.2 형식 (A) | 17 | 0 |
| 공식 `[Background Information]` 형식 그대로 (E) | 187 | 0 |
| 공식 형식 + 배경 블록 안에 용어 (F) | 185 | 0 |
| 용어 뒤에 공식 배경 형식 (K) | 162 | 0 |
| 공식 문체 형식에 분야를 문체로 넣음 (H) | 7 | 0 |
| 공식 기본·용어 형식, 분야 없음 (G) | 0 | 0 |
| 지시문 안에 분야 구절 (J3, 채택) | 0 | 0 |
| 지시문 뒤에 분야를 별도 문장으로 (J5) | 0 | 1 |

한국어→영어 103개에서는 A·G·J3 모두 0개였고 J5는 지시문이 섞인 출력이 1개 있었습니다. 분야 설명을 한국어만으로, 문장 형태로, 다섯 분야를 이어 길게 넣은 경우도 채택 형식에서 양방향 각 0개였습니다(이 네 조건의 출력은 보관하지 않았습니다).

분야 구절을 넣는 것과 빼는 것(G)의 차이는 단어 뜻 선택에서 보였습니다. 예를 들어 `assistant`를 조수·보조원으로, `pilot`을 조종사로 옮긴 출력이 분야 없는 형식에서 더 많았습니다. 정해 둔 몇 개 단어의 표기를 정규식으로 센 값이어서 번역 품질 점수가 아니며, 형식 사이 차이는 이 표본에서 몇 건 수준입니다.

## 확인하지 않은 것

- 실제 마이크·실제 화자·앱 화면에서의 재확인. 위 결과는 지어낸 문장을 모델에 직접 넣은 것입니다. 실제 음성 인식 결과는 더 짧고 끊긴 문장이 많습니다.
- 번역의 의미·자연스러움. 유출이 없다는 것은 번역이 맞다는 뜻이 아닙니다. 같은 입력의 Apple 빠른 번역과 나란히 읽었을 때, 로컬 모델이 더 자연스러운 문장과 Apple에 없던 의미 오류(예: `second half`→"두 번째 단계", `a caveat`→"몇 가지 제한")가 함께 있었습니다. 이 비교는 저장소에 보관하지 않은 1회 열람입니다.
- 오디오·인식 경로, `check-continuous-pipeline.sh`, `check-ui-soak.sh`, `check-dictionary-translation.sh`, `check-local-polish.sh`는 이번에 실행하지 않았습니다. 뒤의 두 검사는 프롬프트가 바뀌었으므로 예전 원자료와 출력이 달라집니다.
- 0.5.3의 dmg는 만들지 않았습니다.
