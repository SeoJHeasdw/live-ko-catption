2026-10-01 · 0.4.5 (13)·0.4.6 (14) 초안 번역 대기와 화면 갱신 대기 줄이기

사용자가 영어→한국어를 더 빠르게 할 수 있는지 진단을 요청했고, 진단 뒤
고정 대기 두 곳의 수정을 승인했다. 음성 인식은 약 1초마다 여러 수정본을
몇 ms 안에 한꺼번에 전달한다. 이전 코드는 묶음의 첫 수정본을 번역하고
최신 수정본은 550ms를 기다렸다. 이제 초안은 원문 갱신이 50ms 멈추면 최신
수정본만 번역하고, 끊이지 않는 갱신에서도 150ms 안에 시작한다. 550ms
초안 간격은 없다. 아래 0.4.4 항목의 550ms 설명은 당시 상태다.
화면 갱신은 고정 100ms 대기 대신 직전 갱신에서 1/30초가 지났으면 바로
그린다. 상세 화면의 따라가기 스크롤 0.2초 간격은 유지했다.

커밋 6ff212f(초안)와 de22568(화면)을 main에 반영하고 각각 push했다.

인식기 병행 실험 (2026-10-01, 제품 코드 변경 없음, 권고: 넣지 않음)

사용자가 준 81.6초 실제 영어 음성 파일 하나를 실제 시간에 맞춰 공급해
SpeechTranscriber(.fastResults)와 DictationTranscriber(.frequentFinalization)를
단독·동시로 한 번씩 실행했다. 파일과 인식·번역 내용은 사용자 자료이므로
저장소에 넣지 않았고 임시 도구도 커밋하지 않았다. 수치만 남긴다.

- 두 인식기는 한 SpeechAnalyzer에서 동시에 동작했다. 프로세스 CPU는
  코어 하나의 1.2%(현재)→2.1%(동시), 발열 상태는 정상이었다. GPU·뉴럴
  엔진 전력은 측정하지 않았다.
- Dictation의 결과 간격은 중앙값 0.30초(상위 10% 0.69초)이고 결과가
  음성보다 0.16초 늦다. 현재 인식기는 0.93초 간격, 0.02초 지연이다.
- 현재 초안 끝에 Dictation의 최신 단어를 덧붙이는 화면을 재구성하면,
  단어를 말한 뒤 영어 원문에 뜨기까지 중앙값 0.72초→0.49초, 느린 10%는
  1.03초→0.75초였다.
- 같은 화면을 Apple로 번역하면 한국어 갱신이 초당 1.0회→2.3회, 이미
  보인 한국어의 절반 이상이 바뀐 횟수가 분당 21회→64회, 다시 쓰인 한국어가
  초당 11자→36자였다. 확정 문장에 도착하는 시점은 같았다.
- Dictation은 82초 동안 확정이 3번뿐(현재 16번)이고 문장 경계를 놓쳤다.
  확정 원문 217단어 중 14단어가 현재 인식기와 달랐고, 숫자 표기 차이를
  빼면 약 8개가 실제 오인식으로 보였다. 앞 단어를 고쳐 쓴 횟수는
  초당 0.36회→1.26회였다. 기준 대본이 없어 현재 인식기의 확정 원문을
  기준으로 삼았다.

약 0.2초를 얻는 대신 한국어 재작성이 3배가 된다. 한국어는 동사가 끝에
오므로 영어 단어가 늘 때마다 문장이 다시 쓰인다. 파일 하나·한 번씩의
결과이며 화면 재구성은 제품 코드에서 실행한 것이 아니다.

사용자 방향

한 화자의 영어→한국어 또는 한국어→영어 실시간 보조 자막이다. 시작 전에 방향을

의역과 일반/IT 설정을 요청했다. 30B MoE와 불필요한 7B를 거절했으며 작은 모델,
메모리, 장시간 발열/팬 소음에 관심이 있다. C/Rust 언급은 언어 선택 강제가 아니라
최적화된 실행을 뜻했다. 일부 자원 사용은 괜찮지만 더 큰 모델이나 형제 서비스를
추가하라는 뜻으로 해석하지 않는다.

완료된 설계와 수정

- 출력 장치와 독립된 입력 전용 AUHAL로 선택한 마이크를 고정한다. 첫 입력과
  끊긴 입력은 20초 기다린다. 무음 버퍼도 정상 입력이다. 오류 종료 후 늦은
  작업을 차단하고 시작 버튼을 즉시 복구한다.
- 화면 응답 없음의 주 표본은 SwiftUI 배치 반복이었다. 네이티브 고정 영역의
  최근 100구절 표시와 제한된 화면 갱신으로 바꿨다. 전체 대화는 모델·저장에
  유지한다. 마이크 레벨 갱신을 창 전체의 배치에서 분리한다.
- 짧은 입력을 변환 큐에서 약 100ms로 묶는다. 콜백에서 언어 엔진은 실행하지
  않는다. 모든 큐는 제한하고 누락은 표시한다. 정지 때 마지막 입력을 배출한다.
- 회색 초안과 현재 원문 수정 버전, 확정, 뒤늦은 번역 차단, 우선순위·취소·
  재시도 경로는 유지한다. 최근 2~4구절/12초/500자 문맥만 다시 번역한다.
- 첫 30분 엔진 검사는 입력은 정상이나 종료 후 네이티브 번역 1개가 반환되지
  않아 실패했다. TranslationSessionLease는 Swift 작업 취소 후 네이티브 응답이
  반환됐을 때만 세션을 정리하고, 실제 미종료 작업을 번역/문맥 각각 2개로 제한한다.
  이 첫 실패 보고서를 통과 결과로 해석하지 않는다. 최종 수정본 결과는 QA 문서를 따른다.
- 진한 글씨는 의미 검증이 아니다. Apple 번역의 중의어·숫자 경계·전문 용어
  오역은 실제 검사에서 남았다. 코드의 임의 단어 치환으로 덮지 않았다.

- 다른 로컬 번역 모델/런타임을 비교하려면 실제 한국어 품질, 대기·문맥 정책,
  첫 로딩/장시간 메모리·열, 배포 크기·라이선스를 함께 측정한다. Swift/Rust/Go로
  언어를 바꾸는 것만으로 의미 정확성이나 무지연을 보장하지 않는다.
- 늦은 정정이 한도 밖의 확정 문장을 바꿔야 하는 경우, 안정된 기록과 수정 알림을
  어떻게 표시할지 사용자가 정한다. 현재는 오래된 문맥 묶음을 고정한다.

다음 세션은 위 후보를 모두 자동 구현하지 말고 사용자의 새 요구사항에 맞춘다.
