0.4.0은 선택적 Hy-MT2-1.8B Q6_K 문장 보완과 일반/IT 설정을 추가했다.
모델은 약 1.47GB이며 사용자의 요청으로 이 Mac에 설치했다. 모델 가중치는
Git과 앱 번들에 없다. 고정된 공식 파일 크기/SHA256 검증 후 Application Support에
원자적으로 설치한다. 기본 OFF이며 IT 용어 참고는 현재 원문에 관련된 작은 목록만
프롬프트에 넣는다. API 키·서버·클라우드 호출·형제 엔진은 사용하지 않는다.

빠른 Apple 초안은 그대로 표시하고 ASR-final 현재 버전만 로컬로 보완한다.
기존 partial이 그대로 확정되면 Apple 결과를 재사용한다. 보완 중에는 회색이고
다음 final이 오거나 대기 중이면 선택 작업을 취소/생략해 빠른 결과를 확정한다.
각 단일 원문에는 이전 배경 문장을 넣지 않는다. 실제 QA에서 이전 문장 섞임이
확인됐기 때문이다. 기존 최근 2~4구절 문맥 lane은 명시적 원문 묶음만 보완한다.
숫자·형식 검사는 의미 정확성 보장이 아니며, 시제/부정/ML 분모 오역이 남는다.
기본 OFF를 유지하고 사용자에게 품질 향상을 보장하지 않는다.

런타임은 고정 llama.cpp C++/Metal을 정적으로 묶은 앱 내부 dylib 하나다.
첫 모델 로딩/Metal 예열은 마이크를 열기 전에 준비한다. 실제 native 작업은
단일 직렬 worker, 작업 ID별 취소, 프리필/토큰 사이 시간 한도 확인을 사용한다.
Swift 작업 취소만으로 네이티브가 끝났다고 취급하거나 실행 중 free하지 않는다.
1.5초 native / 1.8초 선택 보완 한도이며, 단일 보완 실패 시 이번 실행은 Apple을
유지한다. 문맥 native timeout은 그 실행의 추가 문맥 보정을 중단한다.

사용자 방향

한 화자의 영어→한국어 또는 한국어→영어 실시간 보조 자막이다. 시작 전에 방향을
선택해 한 대화 동안 유지한다. 사용자는 기존 지연/번역을 유지하면서 더 매끄러운
의역과 일반/IT 설정을 요청했다. 30B MoE와 불필요한 7B를 거절했으며 작은 모델,
메모리, 장시간 발열/팬 소음에 관심이 있다. C/Rust 언급은 언어 선택 강제가 아니라
최적화된 실행을 뜻했다. 일부 자원 사용은 괜찮지만 더 큰 모델이나 형제 서비스를
추가하라는 뜻으로 해석하지 않는다.

완료된 설계와 수정

- 출력 장치와 독립된 입력 전용 AUHAL로 선택한 마이크를 고정한다. 첫 입력과
  끊긴 입력은 20초 기다린다. 무음 버퍼도 정상 입력이다. 오류 종료 후 늦은
  작업을 차단하고 시작 버튼을 즉시 복구한다.
- 화면 응답 없음의 주 표본은 SwiftUI 배치 반복이었다. 네이티브 고정 영역의
  최근 100구절 표시와 제한된 화면 갱신으로 바꿨다. 전체 대화는 모델·저장에
  유지한다. 마이크 레벨 갱신을 창 전체의 배치에서 분리한다.
- 짧은 입력을 변환 큐에서 약 100ms로 묶는다. 콜백에서 언어 엔진은 실행하지
  않는다. 모든 큐는 제한하고 누락은 표시한다. 정지 때 마지막 입력을 배출한다.
- 회색 초안과 현재 원문 수정 버전, 확정, 뒤늦은 번역 차단, 우선순위·취소·
  재시도 경로는 유지한다. 최근 2~4구절/12초/500자 문맥만 다시 번역한다.
- 첫 30분 엔진 검사는 입력은 정상이나 종료 후 네이티브 번역 1개가 반환되지
  않아 실패했다. TranslationSessionLease는 Swift 작업 취소 후 네이티브 응답이
  반환됐을 때만 세션을 정리하고, 실제 미종료 작업을 번역/문맥 각각 2개로 제한한다.
  이 첫 실패 보고서를 통과 결과로 해석하지 않는다. 최종 수정본 결과는 QA 문서를 따른다.
- 진한 글씨는 의미 검증이 아니다. Apple 번역의 중의어·숫자 경계·전문 용어
  오역은 실제 검사에서 남았다. 코드의 임의 단어 치환으로 덮지 않았다.

다음 세션에서 사용자가 새 요구사항을 정하면 검토할 후보

- 과거 자막을 읽는 동안의 고정된 탐색 화면, 검색·페이지 이동, 자동 저장/복구를
  검토한다. 현재 화면은 최근 100구절이며 전체 기록은 수동 저장한다.
- 현재 작은 일반/IT 목록보다 넓은 이름·전문 용어·표기 방식의 용어집을 검토한다. 음성 인식용 어휘와 번역용 용어를
  구분하고, 엔진의 실제 지원과 사례별 정확성·지연을 측정한 뒤 적용한다.
- 다른 로컬 번역 모델/런타임을 비교하려면 실제 한국어 품질, 대기·문맥 정책,
  첫 로딩/장시간 메모리·열, 배포 크기·라이선스를 함께 측정한다. Swift/Rust/Go로
  언어를 바꾸는 것만으로 의미 정확성이나 무지연을 보장하지 않는다.
- 늦은 정정이 한도 밖의 확정 문장을 바꿔야 하는 경우, 안정된 기록과 수정 알림을
  어떻게 표시할지 사용자가 정한다. 현재는 오래된 문맥 묶음을 고정한다.
